# The Enbraile Bot

The group's Discord bot, `Enbraile`, for the `TemploManchego` server (`757377019536211988`). One Node process in `home/bot/` hosts the bot's features as modules: the [DJ](../../../dj/bot/explanation/bot.md) and [Cari's voice for the zombies runs](../../../zombies/bot/explanation/bot.md). The host holds what Discord allows only once per bot: the gateway connection, the server's slash commands and the voice connection. It also holds what every module needs: the database and the API.

## How It Runs

The process runs in the `dj` namespace of the owner's home Kubernetes cluster, `tom` (two Raspberry Pi CM5 boards, arm64), declared in the owner's `dloez` repository under `homelab/apps/tom/dj.yaml`. A `tailscale` pod beside it publishes the API with Tailscale Funnel at `https://dj.<tailnet>.ts.net`, over an outbound connection, so no port opens on the home network. See [How to Run and Deploy the Bot](../how-to/run-and-deploy-the-bot.md).

The host (`home/bot/src/`) holds:

- the gateway client (`discord.ts`), with the Guilds and Guild Voice States intents.
- the slash commands (`commands.ts`): on every start it registers every module's commands with the server in one call, and routes each command and autocomplete to the module that declared it. A command's reply is deferred, ephemeral if the module asks, and a command that throws answers "That didn't work." in the user's language.
- SQLite through `node:sqlite` (`db.ts`), at `DATA_PATH`, on a 1 Gi Longhorn volume at `/data`, with a `kv` table; each module creates its own tables in the same file.
- the HTTP API behind `INTERNAL_SECRET` (`api.ts`): `/<module>/<path>` goes to that module's route, as the user named by `userId` in the query or body; `/healthz` answers `{"ok":true}`; anything else is 404.
- the live sockets (`api.ts`, `ticket.ts`): a module's route can hand out a ticket, signed for one user and one module and valid for 60 s, which opens `/<module>/live`. The socket gets the module's pushes and answers the same calls as its HTTP routes, as that user, except `ticket`. Every 10 s the host pings each socket, closing one whose last ping went unanswered, and sends a `beat` message.

A module (`home/bot/src/module.ts`) is an object with a `name` and any of `commands`, `route`, `live`, `connect` (a process holding `INTERNAL_SECRET` opening `/<module>/connect`), `start` (run once the gateway is ready) and `stop` (run on shutdown). The modules are listed in `home/bot/src/modules.ts`: `dj`, `zombies` and the host's own `voice`. A module imports only `home/bot/src/sdk.ts`, which exports the client, the server, member lookup, the database, tickets, the voice hub, hearing, Claude and transcripts.

## Voice

A bot can be in one voice channel per server, so the host owns the one voice connection (`voice.ts`) and modules hold leases on it. `voice.hold(owner, channel, { listen })` adds a lease and joins the channel, moving the bot if it was elsewhere; `voice.release(owner)` drops it, and the bot leaves when no lease is left. A module hands the hub the audio player it plays through (`voice.play`), which the hub subscribes to every connection it makes. `voice.members()` lists the people in the bot's channel, read from the gateway's voice states.

The hub rejoins on its own. A connection that has not started reconnecting by itself within 5 s of dropping is joined again at once, and a check every 15 s rejoins one that is still down; after four failed joins in a row it drops every lease and leaves. Modules follow it through `voice.watch` events: `connected` after every join, `lost` when it starts rejoining, `rejoined` when it is back, `gone` when it gives up, `moved` when someone drags the bot to another channel, and `members` when someone joins or leaves the bot's channel.

Each module decides whether it needs to hear the call: the bot is deafened unless a lease asks to `listen`, and when one is added or released the hub changes that on the same connection, without reconnecting (`voice.listening()`). `voice.speak(audio)` queues a clip to say: while it plays, the hub points the connection at its own speech player, so the music player pauses by itself, and points it back when the queue is empty; `voice.speaking()` says whether it is talking. `voice.receiver()` hands out the connection's receiver, which gives one audio stream per person speaking.

## Hearing, Speaking and Claude

The host gives modules what a voice feature needs and no feature of its own. Hearing and speaking run on the [voice worker](../../voice/explanation/voice.md) on the owner's PC, which dials in at `/voice/connect` behind `INTERNAL_SECRET` (`hearing.ts`, a module named `voice`); while it is connected, the bot hears the call when a module holds it with `listen` and has a trigger word or asks for transcripts (stored, or heard through `onTranscript`); a module that only plays, as the DJ, leaves it deafened.

- **Triggers:** `hearing.onTrigger(word, handler, { ack })` registers a word. The host sends every registered word to the worker, lowercased without accents, and Whisper also takes them as hints. When a transcript contains one anywhere, the worker sends the words after it, and the host calls each handler registered for that word with `{ word, userId, text }`; nothing reaches a module through a trigger, or Claude, unless Whisper heard its word. A word alone waits up to 8 s for the same person's next sentence. With `ack` (on by default) the worker plays a short chime as soon as it hears the word. `onTrigger` returns a function that removes the registration.
- **Speaking:** `hearing.say(text, { voice })` has the worker speak the text and plays it with `voice.speak`; it resolves when the audio is queued and fails if the worker is not connected, may not load the voice named, has no voice loaded, answers that the voice failed, or does not answer within 60 s. Without `voice` the worker's default speaks. A voice other than the worker's warm ones is loaded only while a module holds it: `hearing.hold(owner, voice)` asks for it, throwing for a name the connected worker may not load, `hearing.release(owner, voice)` lets it go (every voice the owner holds without `voice`) and `hearing.holding(owner, voice)` says whether it is held, and the worker unloads it when no module holds it; a `say` for a voice still loading waits for it up to 30 s, and one for a voice nobody holds is spoken in a loaded voice. `hearing.voices()` lists the voices the connected worker may load, the ones loaded now and its default ([the voices](../../voice/explanation/voice.md#voices)); `hearing.available()` says whether the worker is connected.
- **Claude:** `claude.ask({ system, messages, tools, userId, model, maxTokens, maxSteps })` sends one request to Claude through the Messages API, runs the tools it calls (each a `{ definition, run(input, userId) }`) for up to `maxSteps` rounds, and returns `{ reply, refused, messages }`. It defaults to Claude Haiku 5.5 with thinking off and low effort, keeps no history and has no prompt of its own. `claude.available()` says whether `ANTHROPIC_API_KEY` is set.

Each person's speech becomes a clip when they stop for 0.8 s, capped at 30 s; clips of under 0.4 s are dropped. The host wraps its Opus packets in an Ogg file (`ogg.ts`) and sends it to the worker with the speaker's ID and the time they started.

## Transcripts

Modules decide whether calls are transcribed: `transcripts.keep(owner, true)` asks for it and `transcripts.keep(owner, false)` takes the request back, and the host stores while at least one module asks and the bucket is configured (`transcripts.active()`; `transcripts.configured()` says whether the bucket is). It then keeps everything said in the bot's call (`transcripts.ts`): every sentence the worker transcribes, and every sentence the bot says. A line holds the time speech started, the channel's ID and name, the speaker's ID and server display name (`Enbraile` for the bot), the text and the clip's length. Every minute, and on shutdown, the lines gathered so far are written to Backblaze B2 through its S3 API, one JSON Lines object per channel at `<yyyy>/<mm>/<dd>/<channel id>/<time of the first line>.jsonl`; a failed write is kept and tried again with the next. It needs `TRANSCRIPTS_ENDPOINT` (the bucket's S3 endpoint), `TRANSCRIPTS_BUCKET`, `B2_KEY_ID` and `B2_APPLICATION_KEY`; without them nothing is stored.

A module can also hear the lines themselves: `hearing.onTranscript(handler)` calls the handler with each sentence the worker transcribes while at least one module keeps transcripts, as the same line that would be stored (`TranscriptLine`), with or without the bucket; the bot's own sentences are not passed on. While a module holds the call with `listen`, keeps transcripts and has a handler registered, the bot hears the call even with no trigger word and no bucket. `onTranscript` returns a function that removes the handler. The host never passes these lines to Claude, and a module must not either: Claude still gets only what follows a trigger word.

## Modules in Other Categories

A module's code stays in its own category (`dj/bot/` for the DJ, `zombies/bot/` for Cari), so the host imports it by relative path. A module has no dependencies of its own: the host's `package.json` holds them all, and `npm ci` in `home/bot/` links each module's `node_modules` to the host's (`scripts/link-modules.mjs`). Node caches a package by its real path, so the host and every module share one copy of `discord.js` and `@discordjs/voice`. A module keeps a `package.json` that only says `"type": "module"`. The image is built from the repository root, so a new module's paths go in four places: `home/bot/tsconfig.json`'s `include`, the `COPY` lines of `home/bot/Dockerfile`, the allowlist in `home/bot/Dockerfile.dockerignore` (which ignores everything else), and the `paths` of `.github/workflows/home-bot.yml`.

## Deploying

A push to `main` touching `home/bot/`, `dj/bot/` or `zombies/bot/` runs `.github/workflows/home-bot.yml` on GitHub's arm64 runner. It runs the gate and builds `home/bot/Dockerfile` from the repository root, pushing `ghcr.io/dloez/enbraile-dj-bot:main-<UTC timestamp>-<short sha>`. Flux in `tom` scans the repository every minute, picks the newest tag (`clusters/tom/dj-image-automation.yaml` in `dloez`), commits it to `dloez`'s `main`, and rolls the pod.

## Decisions

- **One process hosting modules, not one bot per feature:** a bot account can be in one voice channel per server, and a voice feature has to hear and talk in the same call as the music. The one shared Discord application, below, stays. Separate processes talking over RPC were rejected as too much for two Raspberry Pis and one server. _(owner, 2026-11-15)_
- **The host in `home/`, each module in its own category:** `home` holds what the group's apps share, as the shared login does; the DJ's code stays in `dj/bot/`. _(owner, 2026-11-15)_
- **Modules share the host's `node_modules` through a link, not an npm workspace:** a workspace needs a `package.json` at the repository root, which could change how Vercel installs the three web projects. A workspace rooted in `home/bot/` does not work either: Node resolves a module's imports from its real path, outside the host, and refuses to strip types from files under `node_modules`. Checked in throwaway probes, 2026-11-15. _(the agent's choice, 2026-11-15)_
- **Module routes under `/<module>/`:** the DJ's routes moved from `/internal/` to `/dj/`, and the panel with them in the same commit. _(the agent's choice, 2026-11-15)_
- **Slash commands registered on every start,** replacing a script run by hand after each change to them; the one-time clearing of the interactions endpoint URL that script also did is not repeated, since a new application has none. _(the agent's choice, 2026-11-15)_
- **The deployment keeps its `dj` names:** the image `enbraile-dj-bot`, the `dj` namespace, the `dj.<tailnet>.ts.net` address and `/data/dj.db` are set in `dloez`, so renaming them is a change there, left for later. _(the agent's choice, 2026-11-15)_
- **On the owner's cluster `tom`, not Cloudflare:** the bot is one long-lived process holding gateway and voice connections, which Workers, a Durable Object and a Container that woke on demand only imitated, slowly and for about $5–8 a month. Supersedes running on Cloudflare Workers Paid with Containers (2026-11-06) and deploying through Workers Builds (2026-11-07). _(owner, 2026-11-07)_
- **API published through Tailscale Funnel, not a Cloudflare Tunnel:** both are outbound-only, so no port forwarding and the home IP stays private, but Funnel's public relays are Tailscale's own servers rather than Cloudflare's IPs, which Spanish ISPs block during LaLiga matches, so the panel's live socket should keep working then. No report of a LaLiga block hitting Tailscale was found on 2026-11-07; if one does, the panel polls through Vercel as before. The cost is a `ts.net` address instead of an `enbraile.vip` one, which only the panel sees. _(owner, 2026-11-07)_
- **Deployed by Flux image automation pushing straight to `dloez`'s `main`,** unlike pihole's reviewed bumps, so a push to `enbraile` deploys like the panel does. _(owner asked for deploy on push, 2026-11-07)_
- **Either node:** the pod has no node pinning. _(owner, 2026-11-07)_
- **No monthly hour limit:** it only capped the Container bill. _(owner, 2026-11-07)_
- **SQLite on the pod's volume:** one guild and one process, and nothing else reads it; every module shares the file. _(2026-11-07)_
- **One shared Discord application,** renamed `Enbraile`, for login and bot; private, server installs only, with View Channels, Connect and Speak. _(owner, 2026-11-06)_
- **The voice connection and rejoining moved from the DJ into the host,** with the DJ's numbers kept (5 s to recover, a check every 15 s, four failed joins), so every module gets the same rejoin and voice features can share the call with the music. _(owner, 2026-11-15; the lease mechanism the agent's choice)_
- **The bot pauses the music while it talks, rather than lowering it:** with one audio player per connection, lowering the music means decoding and encoding its Opus on the Pi, which the bot never does today; switching the connection to a speech player pauses the song for the seconds of a reply. The DJ's stall watchdog ignores those seconds. _(forced by the single player, 2026-11-15)_
- **Hearing and speaking run on the owner's PC, and the PC dials in:** Whisper large-v3 on its RTX 5090 transcribed Spanish word for word in about 0.25 s a clip in two voice tests on 2026-11-15, which the Pi cannot do; the bot's pod is not on the tailnet and WSL does not expose its ports, so the worker opens the connection, behind `INTERNAL_SECRET`. Hearing works only while that PC runs the worker. _(owner, 2026-11-15)_
- **Primitives, not an assistant:** the host offers triggers, speech and Claude, and each module decides what a trigger does and what it says; a conversational assistant built first as an example was removed. Trigger words belong to the modules that register them. _(owner, 2026-11-15)_
- **Claude only after a trigger word:** Whisper runs on every sentence, but a module gets text to pass to Claude only when Whisper heard the module's word. A module that keeps transcripts also hears every line through `hearing.onTranscript`, to store them (Cari keeps a run's call in the run), and must not pass those lines to Claude. _(owner, 2026-11-15; the transcript feed the owner's, its shape the agent's choice)_
- **A trigger word anywhere in a sentence:** in the second voice test someone said the word mid-sentence, and a rule that looked only at a clip's first words missed it. _(the agent's choice after the test, 2026-11-15)_
- **An optional chime when a trigger word is heard:** in the first test people asked again while a reply was still on its way. _(the agent's choice after the test, 2026-11-15)_
- **Claude through the Messages API with an API key, not the Agent SDK on a subscription:** Anthropic's terms do not allow a Claude subscription to serve other people's requests, and the Agent SDK starts a Claude Code process per session, slow and heavy on the Pi. Claude Haiku 5.5 by default, at $0.10 and $0.50 per million input and output tokens, about $0.15 for 300 short requests. The key is the 1Password field `discord-bot-enbraile/anthropic-api-key`. _(owner, 2026-11-15; the default model and settings the agent's choice)_
- **Conversations transcribed and kept in Backblaze B2 when a module asks,** in the owner's bucket `discord-voice-transcriptions-enbraile`, whether or not a trigger was said; off while no module asks. JSON Lines written every minute, since an S3 object cannot be appended to. _(owner, 2026-11-15; the format and the minute the agent's choice)_
- **Deafened unless a module asks to listen:** the DJ is not controlled by voice for now, so the bot it brings into a call hears nothing; whether to listen is part of each module's lease. _(owner, 2026-11-15)_
