# The DJ Panel

The web panel for the [DJ bot](../../bot/explanation/bot.md), in `dj/panel/`, for `dj.enbraile.vip`. It shows what is playing and offers the player's controls, the queue, playlists, history and, for users with Manage Server, the DJ role, in English or Spanish.

To add music, a user searches and picks from a list of songs, each with its cover, artist, album, play count and length; the play count tells the original from covers and live versions. A pasted YouTube or Spotify link is added directly. The same search adds songs to a playlist. Results come from the bot's YouTube Music song search ([The DJ Bot → Sources](../../bot/explanation/bot.md#decisions)), fetched 250 ms after typing stops. While a new search runs, the old results dim and cannot be added, so a quick click never adds the song from the previous search. In the player's search, the song the user is about to pick is warmed: the top result once it has shown for 600 ms, and any row they point at, touch or focus, each at most once. Warming asks the bot to resolve it ahead ([The DJ Bot → How It Runs](../../bot/explanation/bot.md#how-it-runs)).

The look comes from the [DJ Player Redesign](https://claude.ai/artifact/Pbb3XsptEtoiqnzs7eWoks) canvas in Claude Design: a desktop board and a phone board of the player tab, in a near-black theme with the mint accent, Inter (bundled through `@fontsource-variable/inter`), pill tabs and buttons, and a square cover over the controls. The other tabs reuse its colours and pills. The canvas is a reference, not a signed-off spec: the owner chose not to review it.

A signed-out reader is sent to the [root site](../../../home/site/explanation/site.md) and back. A Vercel function (`api/_lib/app.ts`) reads the session from the root's `/api/me` and forwards calls to the bot's API at `BOT_URL` with `INTERNAL_SECRET`, so the Discord user ID comes from the session, never the browser. Locally, `DEV_USER_ID` stands in for a session.

Until that call answers, the page shows the header and a pulsing outline of the player, so a cold function start reads as loading rather than a blank page. On load the page makes one function call, `/api/me`, which returns the reader's access with the player's state and a live ticket, read from the bot at once, so the player shows and the socket opens without another round trip. Live updates arrive by a WebSocket straight to the bot, through Tailscale Funnel, opened with a ticket that names the user and lasts a minute. While the socket is open, every call except `/api/me` and the ticket goes over it instead of through the function, and the bot checks the ticket's user's access on each one ([The DJ Bot → How It Runs](../../bot/explanation/bot.md#how-it-runs)). Spanish ISPs block Cloudflare's IPs during LaLiga matches ([The pkmn Site → Decisions](../../../pkmn/site/explanation/site.md#decisions)), so the page itself is on Vercel, and when the socket fails, calls go through the function again and the page polls through it every 10 seconds, retrying the socket after 1, 3, 10 and then every 30 seconds, and says so once a retry fails.

### Feeling Live

A control changes the page as soon as it is pressed: pause, resume, skip, seek, loop, autoplay and queue edits and adding a song from the player's search, apply a prediction of the bot's next state (an added song shows at once as starting or at the end of the queue, and its result is ticked; if the bot refuses, both are undone and the reason shows), which the bot's reply or broadcast then replaces; a failed command reloads the state. Each view the bot sends carries the position at that moment, and the page counts on from when it arrived. While a song loads (`loading`: picked but no audio yet), the clock stops at its start and reads "Starting…", the progress bar pulses and the play button spins, so the time never runs ahead of the audio. Vercel project `enbraile-dj`, root directory `dj/panel`, deploys every push to `main` that touches `dj/panel/`, set up as the [root site's](../../../home/site/how-to/deploy-the-site.md) is; its Production variables are `ROOT_URL`, `BOT_URL` and `INTERNAL_SECRET`.

## Decisions

- **On Vercel with `dj` as a DNS-only record:** the page and its controls stay reachable during a block. Polling is not the normal path because pkmn shares Vercel Hobby's 1M calls and 4 CPU-hours a month. _(2026-11-06)_
- **Redesigned in Claude Design, without review:** the owner asked for a minimalist modern player and did not want to review the design. This replaces the first plain page, which had no Claude Design boards. It stays plain CSS rather than shadcn, since the panel has few controls. _(owner, 2026-11-07; the look the agent's choice)_
- **No volume control on the panel:** each listener sets the bot's volume in Discord, and changing it on the bot restarts the stream. The bot's `/volume` command remains. _(owner, 2026-11-07)_
- **Search, then pick:** typed text lists matching songs to choose from, never adds the top hit blindly; links still add directly. _(owner, 2026-11-07)_
- **Starting needs the caller in voice:** the bot joins their channel; if a session is running, anything added goes to its queue. _(owner, 2026-11-07)_
- **Calls over the live socket, and controls that answer before the bot:** a click went browser → function → root `/api/me` → Funnel → bot and the page waited for all of it. Measured against a stand-in bot on 2026-11-07, a control now changes the page in 31–36 ms. The function stays the fallback, so a LaLiga block still leaves the controls working. _(owner asked for a more responsive player, 2026-11-07; the mechanism the agent's choice)_
- **Warm the likely pick:** a song picked with nothing playing waited the whole resolve, 8.7 s on `tom`. Against a stand-in with that resolve time, reading results for 3 s before adding the top one cut the wait to 6.5 s on 2026-11-07. Warming costs a yt-dlp run for songs nobody adds, so the bot caps it. _(owner asked for faster starts, 2026-11-07; the mechanism the agent's choice)_
- **One call to load:** `/api/me`, then the state and a ticket, were two rounds through the function, each checking the session with the root site again. `/api/me` now carries both; on 2026-11-07 the root's `/api/me` took about 0.23 s warm and the function about 0.11 s, so the saved round is roughly half a second, and two function calls a visit. _(owner asked for a more responsive site, 2026-11-07; the mechanism the agent's choice)_
- **Playlists:** one owner edits each, and anyone allowed can browse and play it. _(owner, 2026-11-07)_
