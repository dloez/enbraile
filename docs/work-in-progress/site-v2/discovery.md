# Site v2: Accounts, Snapshots and Team Building

Scoped with the owner on 2026-10-22.

## Goal

The site stops being a shelf of standalone tools and becomes the way a player of the group builds their teams. Each player signs in, sees the PC (with its bag and TMs) of every series they play as **snapshots** taken at milestones, and builds teams from any snapshot, or from Pokémon made from scratch, with the full analysis that today lives in Open Sheet's Team view and the Team Analysis tool. The site knows which series is being played, on what game, and when the group fights.

Done when, on `pkmn.enbraile.vip`: a player the admin has allowed signs in with Discord, lands on the current series' page, uploads their save zip and sees it as a snapshot; opens any player's PC at any snapshot; and builds, analyses, compares and copies teams stored in their account. `/open-sheet`, `/team-analysis` and the "tools" home page are gone.

## Decisions

### Accounts and Access

- **Q: How do players sign in?** A: Discord. **Why:** one click, no passwords, and the Discord name is how the group knows each other.
- **Q: Who can get in?** A: An allowlist kept by the admins: anyone can sign in with Discord, but sees nothing until an admin adds them. **Why:** the PCs are the group's own; no invite links to manage.
- **Q: What is an admin?** A: A separate, local account (username and password, signed in at `/admin`) that is not a player: no saves, no teams, no Discord. The owner plays under their own Discord account like everyone else. **Why:** the owner: a player building a team should not carry admin powers.
- **Q: How are admin accounts made?** A: A script run against the database (`npm run admin:create <name>`, which asks for the password). No sign-up page; admins cannot make admins. **Why:** nobody can make themselves an admin through the site.
- **Q: What does an admin do?** A: Everything in an admin UI: creates games and series, keeps the allowlist, picks a series' players, and can upload a save for any player. **Why:** the owner chose an admin UI over code for series and players.
- **Q: What is a game?** A: An admin-made entry (name, e.g. "Pokémon Añil + Randomlocke") with an uploaded zip of the game files, linked to one or more series. Players of a linked series download it from the series page. **Why:** the owner: games are made once and reused by many series.
- **Q: What does creating a series take?** A: A draft series is edited freely: number, name, game, background scene (from a fixed set, [Look](../../pkmn/site/explanation/site.md#look); owner, 2026-10-22), players, milestones (e.g. Gym 1, 2, 3, 5, 7 and Post-League) and rules. Starting it is gated by a checklist that shows what is missing: rules written, a game chosen that has an uploaded file, at least two players, at least one milestone. A series is draft, running or finished, and the running one is the current series players land on; one runs at a time. **Why:** the owner asked for the checklist; one running series is _proposed_, from "we are currently playing series 2".
- **Q: What are a series' rules?** A: Markdown text written in the series form, which can start as a copy of another series' rules and stays editable after the series starts; every player reads it on the series page. Series 1's starts as a copy of [Series 1 Rules](../../pkmn/series/1/reference/rules.md). The site enforces nothing from it yet. **Why:** the owner; enforcing rules in team building is a backlog idea.

### Model

- **Q: What are the pieces called?** A: Game → series → save → snapshot. A series is played on one game, and a game serves many series. A player has a save per series; a save holds snapshots, each taken at a milestone ("Gym 3", "Post-League"). "Box" stays the game's meaning: a page of the PC. **Why:** the owner's pick.
- **Q: What does a snapshot hold?** A: Everything the save holds at its milestone: the living Pokémon; the fainted ones (`perma_faint`), listed by species, nickname and level; the whole bag, all 8 pockets (the export today reads only pockets 1 and 5 and pocket 4's TMs); the TMs with their rolled moves; the trainer's name, ID, money and badges; the party and its levels; play time, Pokédex seen and owned, and the routes whose first encounter is used. Each snapshot keeps its own copy, so the site shows how a trainer stood at each milestone, as a timeline, not only their latest state. Play time and the Pokédex were located in MIRAMEEE's save ([State → Save Records](../../pkmn/games/anil/reference/state.md#save-records), 2026-10-23). A save keeps no time per badge or gym attempts. **Why:** the owner. _(owner, 2026-10-23; widens "each one PC export (Pokémon, bag, TMs)")_
- **Q: Admin overrides?** A: An admin can set any value derived from a save by hand: progress, the fainted count, a snapshot's milestone. Each such value records its source, from the save or set by hand (by whom and when), and a value set by hand wins over the save's until an admin clears it. **Why:** the owner. _(owner, 2026-10-23)_
- **Q: How many saves per series?** A: One per player, shown to the player as series → snapshot; the save stays in the model underneath. Uploading again to a milestone replaces its snapshot. **Why:** the owner: only one save per series is supported, with overwrites.
- **Q: Series 1?** A: One snapshot per player, "Post-League", since only the post-League PCs exist.
- **Q: What can players see of each other?** A: Everything, for now: every PC at every snapshot, and every team. **Why:** the owner: "I would not worry about this now". Showing only what a series' rules allow (the league's box sheet) is a later idea.

### Snapshots In

- **Q: How does a save reach the site?** A: Each series has an ingestion mode, set in the series form: manual or automatic. In a manual series the player uploads their save zip (below). In an automatic one, later, the modded game sends the save by itself and players never see the upload; there is no endpoint for it now. In both, an admin can upload, replace, delete or move any snapshot, for any player, and both go through one pipeline: a raw save is stored, exported, and becomes a snapshot; only the source differs. **Why:** the owner; the end goal is games that report by themselves, but series 1 is near its end and Añil will not be modded again for this, so manual comes first and the model must not assume it. _(owner, 2026-10-23; replaces "The client app that reports gym progress and makes snapshots by itself? Later, out of this idea")_
- **Q: How does a snapshot get in?** A: The player uploads the zip of their save folder (`%APPDATA%\Pokemon Anil`), picks the `Partida N.rxdata` slot when there are several, and picks the milestone. An admin can do the same for any player. **Why:** the owner; most players are not technical.
- **Q: The snapshot's milestone?** A: Suggested from the save, its badges and Hall of Fame (5 badges → "Gym 5"); the player or an admin can change it before saving. A milestone the save cannot know, such as a tournament, is picked by hand. **Why:** the owner. _(owner, 2026-10-23)_
- **Q: TM rolls the export makes?** A: Rolled at export as today and kept. The player can download their zip back with the slot's side file (`tm_compatibility_<slot>.dat`) holding the rolls, to extract into the save folder with the game closed. The site keeps a save's rolls, and reuses them when it exports that same zip again, until the player uploads a new zip, whose own rolls (side file, else save) then stand, with what they still lack rolled anew. The new zip should hold the site's rolls but may not, and the site never compares one snapshot's TMs with another's: manual ingestion trusts the players. **Why:** the owner: rolled TMs belong in the snapshot, and players are trusted. Reusing the rolls on a re-export is forced by the game's code: a roll counts only once the game loads the side file and the player saves, so rolling again could come out the other way ([Open Sheet Export → Rolling TMs](../../pkmn/games/anil/explanation/open-sheet-export.md#rolling-tms)). _(owner, 2026-10-23; replaces "made in memory and thrown away")_
- **Q: Moves?** A: Always exported (known, relearner and TM moves); the `--moves` flag goes. **Why:** the owner thought it was already the default; it is still opt-in at `export_data.py:6867`.
- **Q: Exports from older versions of the export script?** A: Supported, for every series: the upload also takes an export `.json` (player or admin), and every export, old or new, is read as far as it goes and never refused for missing data. A missing field reads as absent and the snapshot carries a warning naming what is missing (e.g. "no IVs, EVs or stats · no moves"), shown on its series page row and its PC page; an entry with no usable species is skipped and counted in the warning. Only a file that is not JSON or holds nothing usable is refused. The views already cope: Level 50 ranges without IVs, any Gen 1–5 move without `moves`; `moves` from before TM rolling are marked unchecked. **Why:** the owner; series 1's MIRAMEEE (2026-10-17: no IVs, EVs or stats, unrolled TM moves) and Vicky (2026-10-16: no IVs, EVs, stats or moves) exports cannot be made again with the current script, and the site never stops working for a gap.
- **Q: Uploaded save zips?** A: Kept in the file store (Backblaze B2, below), so snapshots can be re-exported when the export improves.

### Pages

- **Q: First page after sign-in?** A: The running series' page, as signed off on 2026-10-22 (`pkmn/site/design/series.dc.html`): a header drawn on the series' scene with its name, and the game in a box with its download; the League, shown as a work-in-progress placeholder; the Trainers, one row per player with their progress along the milestones (rounds and the tournament marked), each row opening into tiles for their PC (count, opens it), their teams (count, opens them) and their snapshots (each opens the PC at it), plus the export's missing-data warning; and the rules. No series switcher on the page: the Series tab leads to the list. Where the upload starts is part of the upload flow's design. A signed-in player not on the allowlist sees that they are waiting to be added. _(owner, 2026-10-22; replaces the upload button on the player's row and the series switcher)_
- **Q: The series list?** A: `/series`, the Series tab's page (`pkmn/site/design/series-list.dc.html`): one banner per series, newest first, drawn on its scene with its name, its game and its state (playing now, finished), the whole banner a link that lifts on hover. _(owner, 2026-10-22)_
- **Q: Top-level sections?** A: Series · PC · Teams · Admin (Admin for admins only). PC opens the signed-in player's own trainer page in the current series (2026-10-23); every other trainer page is reached from the series page. Routes: `/series`, `/series/<n>`, `/series/<n>/players/<player>?snapshot=<milestone>` (which PC opens for the player's own), `/teams`, `/teams/<id>`, `/admin`. _(owner, 2026-10-22: PC added as its own section)_ No "tools" anywhere. **Why:** the owner dislikes "tools" as a concept: they read as standalone. This takes over the backlog's "series hubs" idea.
- **Q: The trainer page?** A: `/series/<n>/players/<player>` is the trainer's page, with tabs Journey · PC · Bag under one snapshot picker. Journey shows the trainer's records across their snapshots, one column per milestone: play time, badges, money, Pokédex seen and owned, trainer battles won and lost, blackouts and the fainted count. **Why:** the owner wants to see how a trainer was doing at each point of the game; the party was dropped from it, since "it does not make much sense" (2026-10-23). _(owner, 2026-10-23; replaces the PC page)_
- **Q: The fallen?** A: Listed on the trainer page: sprite, nickname, species, level, and the span of milestones in which each fell, found by comparing a trainer's consecutive snapshots (alive in one, permafainted in the next). Their count is the series row's Fainted tile. _(owner, 2026-10-23)_
- **Q: Comparing trainers?** A: A switch on the series page's Trainers table swaps the progress track for each trainer's records at a chosen milestone: play time, fainted, Pokédex, battles. No ranking: the league owns rankings. _(owner, 2026-10-23)_
- **Q: The progress track?** A: It shows the trainer at their latest snapshot, and the row's tiles show that snapshot. Where they have snapshots the track is interactive: clicking another milestone's node shows that snapshot in the row. Progress an admin set by hand ([Admin overrides?](#model)) is marked as such. _(owner, 2026-10-23)_
- **Q: Does the site cover the league?** A: Yes: the site will hold the league (matchdays, standings, the Pokémon League, the cup), integrated with teams, and the group's Trainer League app moves into it, its Wonder tab aside. Site v2 only shows a work-in-progress placeholder for it on the series page; the league is designed and built later as its own idea ([Backlog → pkmn/site: the league](../backlog.md#pkmnsite-the-league)). **Why:** the owner. _(owner, 2026-10-22)_
- **Q: Design?** A: A Claude Design pass on the [Site v2 Screens](https://claude.ai/artifact/JZpaCYGx2NQtPpcvAWYXrZ) canvas, signed off in parts so building can start: the series list, the series page and the header on 2026-10-22, in a new look that replaces the Open Sheet look everywhere ([Look](../../pkmn/site/explanation/site.md#look)); then sign-in and waiting on 2026-10-23; then the upload flow, the trainer page (2026-10-23: it replaces the PC page), the team list and the team builder. Each signed-off board is frozen in `pkmn/site/design/`. The admin pages are not designed: they are built in the look from its shared pieces. Phone layouts come with each screen's design. **Why:** the owner chose a design pass first; signing off in parts lets the build run in another session while design goes on. _(owner, 2026-10-22; admin pages built without a design of their own: proposed)_

### Team Building

- **Q: Where do members come from?** A: A team lists its sources explicitly: any number of snapshots, any player's, each with its own item and Mini Seta limits, and/or "Any Pokémon", which allows free members. The team page shows them as chips; one can be added or removed, unless a member still uses it. A tournament creates teams whose sources it locks, so players build only from what that match allows. The add-a-member dialog has one tab per source. **Why:** the owner: fights, theorycrafting and scouting an opponent; a locked source list is how a PvP match fixes what may be used. _(owner, 2026-10-23; replaces free members on any team)_
- **Q: A new team's sources?** A: The player's latest snapshot in the current series, the one they are probably building for; any combination can be picked instead.
- **Q: Item limits across several sources?** A: Each member draws its item from its own snapshot's bag, and Mini Setas from its own snapshot's count. Free members are counted against nothing. _(proposed, follows from per-snapshot limits)_
- **Q: Free members?** A: A full Showdown set: any species in the team's pool, any item, ability, nature, EVs, IVs, level and four moves, marked as free.
- **Q: A pasted Showdown team with Pokémon the sources can't back?** A: The backed ones match as today; the rest come in as free members when "Any Pokémon" is a source, or are left out when it is not, listed in the dialog either way. **Why:** the owner; when tournaments run inside the site, a tournament will force a team's sources.
- **Q: Who sees a team?** A: Everyone (read-only); only its owner edits it.
- **Q: The pool?** A: Per team, with Team Analysis's pool bar, defaulted from the series (series 1: Gen 9 data, species up to Gen 5, fully evolved).
- **Q: How do the PC and the team pages split?** A: The PC is a read-only view of a snapshot (box, summary, bag); its one link to teams is "Add to team" in the summary, a menu of the player's teams and "New team", which opens the team with that Pokémon added. The team page is built around its six members: each a card edited in place (item with what the bag has left, ability with its Mini Seta cost, four moves picked from what it can learn), the analysis beside them; an empty card opens the PC in a dialog (the team's PCs, box and summary, plus "Any Pokémon" for free members) to put one in that slot. The panel beside the cards shows what is being looked at: the team's analysis by default; a member's summary (the PC's Info · Stats · Moves, over that member's set) when its header row (sprite, name and source, ending in a chevron toward the panel) is clicked; an editor when its item, ability, a move or Set is clicked, whose back and apply return to where it was opened from. The summary is one component shared by the PC page and the team page _(owner, 2026-10-23)_. The Teams tab lists every team, the player's first and others' read-only, with Compare (`Pc`, `Team` and `TeamsList` boards in [Site v2 Screens](https://claude.ai/artifact/JZpaCYGx2NQtPpcvAWYXrZ)). **Why:** the owner; the PC records what the save holds and the team is what is edited, so each page does one job, every edit (free members too) happens in one place, and others' teams reuse the team page read-only. _(owner, 2026-10-23; replaces a builder laid out on the PC page)_
- **Q: Compare, Speed Tiers, Tera?** A: All come over. Compare puts 2–4 of the player's teams side by side (theirs, including ones built from others' snapshots); Speed Tiers joins the views; Tera shows when the pool's gen is 9.

### Data, Stack and Config

- **Q: Backend?** A: Full TypeScript: a Hono API in `pkmn/site/api/`, deployed as Vercel Functions through Hono's Vercel adapter and run locally on Node behind Vite's proxy, so one `npm run dev` serves both without `vercel dev`; Neon Postgres (Vercel Marketplace, free tier) through Drizzle with `drizzle-kit` migrations in the repo, Better Auth (Discord, plus username/password for admins) with its Drizzle adapter, zod schemas shared by browser and API. **Why:** the owner wants one backend language, preferring Python only if it lost nothing; TypeScript has Better Auth and shared types, and the frontend is TypeScript anyway. All of it is free at the group's size; Supabase was turned down because a free project pauses after a week idle.
- **Q: Where do files live?** A: Backblaze B2 (S3-compatible, through the AWS S3 SDK), for game zips (~600 MB each) and save zips alike. Uploads go straight from the browser to B2 with presigned URLs, since a Vercel Function body is capped at a few MB; downloads are short-lived presigned links for players of a linked series. **Why:** the owner; Vercel Blob's free allowance is about one game download round a month, and Cloudflare R2's URLs sit on the IPs Spanish ISPs block during LaLiga matches.
- **Q: The export?** A: Ported to TypeScript in the site; `export_data.py`'s embedded `DATA` table (about 6,150 of its 6,934 lines) becomes a JSON file that `generate_export_data.py` writes for the site, and its ~750 lines of logic (Ruby Marshal reader, abilities, TM rolls, items) are ported. `export_data.py` and its CLI docs are retired. **Why:** the owner chose full TypeScript and retiring the Python CLI, since players now upload on the site.
- **Q: Browser data today?** A: Dropped: Open Sheet's IndexedDB tabs and teams and Team Analysis's `localStorage` drafts are deleted once accounts land; series 1's PCs come back as uploads and teams by Showdown paste. **Why:** greenfield.
- **Q: Environments and secrets?** A: Production on its own Neon branch, previews on a `dev` branch; local dev on `docker compose` (Postgres, and MinIO standing in for B2 through the same S3 SDK), so it needs no cloud account and resets at will. Discord sign-in is registered for production and localhost; previews sign in as an admin or not at all. Secrets (database URL, Better Auth secret, Discord client, B2 key) live in Vercel's environment and `.env.local`, never in the repo.
- **Q: Rollback?** A: Code by Vercel's Instant Rollback or a revert; schema by a forward migration (no down scripts); data by Neon's point-in-time restore.

### Observability and Verification

- **Q: Logs?** A: Vercel's function logs; a failed upload shows the reader why. No analytics, as now.
- **Q: Checks?** A: `npm run gate` (`tsc -b`) covers browser and functions. Beyond it, Claude checks every slice by driving the real site, backend to browser: the Playwright MCP server (in the repo's `.mcp.json`, `WAYLAND_DISPLAY=""` for WSL) on the local stack, signing in as a test player or an admin, then reading the database and the file store. A `verify-site` skill and a how-to doc say how. It is a driver, not a test runner: no test files and no gate step (root `CLAUDE.md`). **Why:** the owner asked that Claude can check the whole site in a real browser; unlit's Playwright MCP setup is the model.
- **Q: Local data to check with?** A: A seed script (admin, test players, a game, series 1) for a known state after a reset, uploading snapshots from `pkmn/site/saves/`, a gitignored folder where the owner puts real save zips and exports (MIRAMEEE's and Vicky's old exports are there). **Why:** the owner confirmed the seed is for checking; players' saves never enter the public repo.
- **Q: Signing in without Discord locally?** A: A dev-only sign-in for test players, enabled by an environment flag production never sets. Discord itself is checked by hand on production.
- **Q: Versions?** A: The latest stable of everything set up here, pinned exactly, Playwright MCP included; nothing copied from unlit's versions. **Why:** the owner.

## Out of Scope

- The client app that reports gym progress and makes snapshots automatically.
- Showing only what a series' rules allow of others' PCs.
- Building the league (matchdays, results, the Pokémon League, the cup): site v2 shows it as a placeholder only ([Pages](#pages)).
- Writing TM rolls into the player's save itself; the rolled zip is the player's to extract.
- Games other than Añil: any game can be created and downloaded, but the save upload reads Añil saves only, until a series is played on another game.
- Enforcing a series' rules in the site (e.g. one legendary per team): a backlog idea.
