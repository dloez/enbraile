# The Zombies Site

The site in `zombies/site/`, for `zombies.enbraile.vip`, where the group will start runs on a map and talk to the coach, Cari. Today it lists the maps Claude has published, and members start or join a run on one and talk in its shared chat, where Cari answers with the prepared hints; following progress, holds and feedback come next ([Zombies Coach](../../../work-in-progress/zombies-coach/discovery.md)). Its look is in the [Site Design System](../reference/design-system.md).

## How It Is Built

It mirrors the [DJ panel](../../../dj/panel/explanation/panel.md): a Vite + React page, and one Hono function, `api/index.ts`, holding every route in `api/_lib/app.ts`. A signed-out reader is sent to the [root site](../../../home/site/explanation/site.md) and back: the function reads the session from the root's `/api/me` with the reader's cookie, so the site keeps no sign-in tables of its own. Locally, `DEV_USER_ID` stands in for a session: it holds a comma-separated list of members, each `<id>` or `<id>:<name>`, and `GET /api/dev/sign-in/<id>` sets a cookie that makes that browser one of them (the first one otherwise), so one machine can be two members of one run. The route answers 404 wherever `DEV_USER_ID` is unset, as it is on every Vercel deployment. The chrome is in English or Spanish, following the reader's `lang` cookie as the other sites do.

Maps live in their own Postgres database, never pkmn's, through Drizzle with `pg` as in [the pkmn site](../../../pkmn/site/explanation/site.md); the migrations in `drizzle/` run in the Vercel build. Its tables:

| Table | Holds |
|-------|-------|
| `maps` | One row per published map, keyed by game and map slug, with its latest version |
| `bundle_versions` | Every published bundle, numbered per map, with the SHA-256 of its canonical JSON and who published it, always `claude` |
| `runs` | One row per run: its map, the language Cari speaks, who started it, when Cari last asked the round, and the lease that lets one of Cari's replies run at a time |
| `run_members` | Each time a person joined a run, with when they left it; a unique index over the rows not left keeps a person in one run at a time |
| `messages` | The run's chat, each line from a member or from Cari |
| `run_knowledge` | The knowledge entries known in a run; an entry without a row is unknown |
| `hint_cards` | A hint card: the ladder it belongs to (a step, or one of its parts) and the Cari line it hangs under |
| `deliveries` | Every rung given, in order: its card, ladder, rung, Alt, level, the wording as delivered, its `mentions` and `reveals`, the bundle version and who asked |
| `coach_calls` | Every Claude call: model, tokens, latency, stop reason, refusal and its category, the rules code caught the model breaking, and any error |

## Map Bundles

A bundle is everything the live coach will need about one map, as one JSON document checked by the zod schema in `shared/bundle.ts`: the map's name in each language, which drawn plan stands for it, the knowledge entries with their `known` or `unknown` marks, the steps (`requires`, conditions, `optional`, the `onSuccess` line, the ladder, part ladders and heads-ups), the map's own calibration notes, and the dossier and sources as the durable copy. Every rung, each of its Alts (with `when` it replaces the rung) and every `onSuccess` line carries its wording in Spanish and English, the knowledge entries it `mentions`, which must already be known, and those it `reveals`; a heads-up carries its `mentions` only. The schema rejects a `mentions`, `reveals` or `requires` that names nothing, and repeated IDs.

A real map's bundle is not written by hand: `npm run compile -- <dir>` builds it from the files the ee-coach skill prepares in that map's dir ([Research and dossier building → Compile and publish](../../../../.claude/skills/ee-coach/references/research.md#4-compile-and-publish)) and writes `<dir>/bundle.json`. It reads `map.json` (the names and art plan), `hints.md` and `hints.es.md` paired line by line, the `L4 as spoken` and `Conditions` of each step in `dossier.md` (each indented `- ` item one condition, an indented line without one joined to the item above), `knowledge.md`, the map's `calibration.md` and every file under `sources/`, and checks what the schema cannot: that both languages hold the same lines with the same IDs, that a line reveals only what it mentions, and that no card text carries a step, hint or level number. Its messages name a file and line or a step and rung, never the text, and its summary is counts only, so its output can be quoted where the players read.

`npm run publish -- <dir>` reads `<dir>/bundle.json`, checks it, and sends it to `PUT /api/claude/maps/<game>/<map>` with `CLAUDE_TOKEN`. The function stores it as a new version, published by `claude`, unless its digest equals the latest one's, so publishing the same bundle twice leaves one version; an older bundle published again becomes the newest version, which is how a map is reverted. Real maps' bundles stay in the gitignored `zombies/maps/<game>/<map>/` ([Repository Layout](../../../general/explanation/repository-layout.md#decisions)); the one committed bundle is the made-up test map in `zombies/site/test-map/`, Harrow Station.

`/api/claude/` is the site's machine API, and it is Claude's: only Claude Code calls it, from the terminal, and every route under it answers 403 to any request without `CLAUDE_TOKEN` as its bearer token, whatever cookie it carries. What it writes is recorded as Claude's, as `published_by` is on a bundle version; the run reads, watch stream and step-ins still to come will join it under the same token and carry the same attribution.

The maps page reads `GET /api/maps`, which returns each map's game and map IDs, its names, its `art` plan key, test flag and version and nothing else from the bundle, so no solution reaches a browser. The same reply carries each map's open runs and the reader's own run.

## Runs

A member starts a run from a map's row on the maps page, choosing the language Cari speaks (Spanish unless they pick English): `POST /api/runs`. Anyone signed in can join an open run from its row or its link, `/runs/<id>`, which shows the run's sheet to a reader not in it and the run to a member (`POST /api/runs/<id>/join`). A person is in one run at a time, so starting or joining a run leaves the one they were in. Nothing closes or ends a run: every run stays on its map's row, even once everyone has left it, and can be joined again.

A new run's knowledge marks are the latest bundle's `known` entries plus every entry known in the starter's earlier runs on that map; each member who joins adds what was known in their own earlier runs there.

The run page polls `GET /api/runs/<id>/messages?after=<last id>&rungsAfter=<last rung id>` every 2 seconds for new lines, the current members and every hint card that gained a rung or arrived with a new line, each card carrying its rungs' wording and whether it shows More. `POST /api/runs/<id>/messages` adds a member's line and answers with Cari's reply as it is spoken. Both answer 403 to anyone not in the run.

## Cari

Cari is Claude, `COACH_MODEL` (Haiku 5.5, `claude-haiku-5-5`, unless set) with `ANTHROPIC_API_KEY`, called by the function on every member's line; without a key she stays silent. The model never writes a hint: it acts through three tools, and code decides what each may do.

- **`give_hint`** hands over the next rung of one ladder, or one of that rung's Alts. Code gives only a rung whose `mentions` are all known in the run (its `reveals` may still be unknown, since it is the line meant to give them away), one per reply, level 4 only when the model says the players asked for the answer, and records the delivery and adds the rung's `mentions` and `reveals` to `run_knowledge` in the same transaction.
- **`mark_known`** takes the players' words; code marks known every unknown entry whose name, in either language and without its article, appears both in them and in a member's line among the last 24, so the model cannot mark something only a rung named.
- **`ask_round`** adds the run's fixed question about the round to the reply, at most once every 10 minutes and never in a reply that gives a hint.

The prompt is a system prompt distilled from the ee-coach skill's session rules, then the run's state: its language, the names of the entries known, each opened ladder with the rungs given and the next rung and Alts code would allow, and the first rung of each ladder not opened yet whose `mentions` are known, leaving out optional steps. An Alt whose `when` names an unknown entry is left out. Ladders are named by handles (`s2`, `s2p1`), never by their step's title, so the dossier and the titles stay out of it, and an unknown entry's name reaches the model only inside a rung meant to reveal it, which is one of the rungs it may give. The last 24 lines of the chat are the conversation, with each card's rungs under Cari's line in brackets.

Her own words are streamed to the asker sentence by sentence as newline-delimited JSON, while the run page shows her row "transmitting" with the blinking caret; a sentence naming an unknown entry or holding brackets is dropped and recorded as a violation instead. When the reply ends, her line and its card are stored together and every member's next poll shows them. A card's More asks `POST /api/runs/<id>/cards/<card>/more`, which gives the ladder's next rung onto the same card in code, without a model call, when that rung is allowed; when it is not, the model is told More was pressed and chooses an Alt or asks what they see. More shows only on the newest card of its ladder, and never when the next rung is level 4.

Each Claude call is a row in `coach_calls`, and each rung a row in `deliveries`, so a run's whole hint history can be read back against its marks.

## Hosting

Vercel serves the site from the owner's Hobby team as the project `enbraile-zombies`: the Vite build's static `dist/` and the API as a Vercel Function (`api/index.ts`) in the same project, as pkmn's and the DJ panel's are. `vercel.json` runs the function in Frankfurt (`fra1`), beside its Neon database (`aws-eu-central-1`), and rewrites every path but `/api/` and `/assets/` to `/index.html`. The database is the Neon project `zombies`, its own and never pkmn's, with a `main` branch for production and a `dev` branch for previews. The `zombies-site.yml` workflow deploys pushes to `main` touching `zombies/site/` to production, and other branches' pushes as previews, which Vercel's Deployment Protection keeps to the team ([How to Deploy the Vercel Projects](../../../general/how-to/deploy-vercel-projects.md)). The function also reads `ANTHROPIC_API_KEY` and `COACH_MODEL`, set in Production. `zombies.enbraile.vip` is on the project's domains and is to be a DNS-only (grey-cloud) `CNAME` to the Vercel target in the `enbraile.vip` zone on the owner's Cloudflare account; until the owner adds that record the name does not resolve. It is DNS-only for the reason pkmn's is: Cloudflare's proxied IPs are blocked by Spanish ISPs during LaLiga matches ([The pkmn Site → Decisions](../../../pkmn/site/explanation/site.md#decisions)). The root site lists the domain in its `trustedOrigins`, so sign-in returns to it. Setting it up is in [How to Run and Deploy the Site](../how-to/run-and-deploy-the-site.md#8-set-up-production-once).

## Decisions

- **No numbers, no step list, the UI is never a hint:** no step or hint numbers anywhere (the terminal's "Step 5 · hint 2/4" is not shown), no list of steps, and no buttons or suggestions that tell players what to try. _(owner, 2026-11-15)_
- **Hints as cards:** one shared chat with Cari, where hints arrive as cards with a generic "more" control and the three feedback controls (too obvious, right, too vague); a level-3 zone shows under its card. _(owner, 2026-11-15)_
- **Cari's voice only:** no chimes or clips on a new hint, since a cue would itself carry meaning. _(owner, 2026-11-15)_
- **One `bundle.json` per map dir:** `publish` takes the dir that holds a map's files, and `compile` writes the bundle there. _(the agent's choice, 2026-11-15)_
- **Bundle IDs from the prepare files' numbers:** steps become `step-<n>`, a step's part ladders `part-<n>` in order, and knowledge entries their `K` IDs in lowercase, so the bundle needs no second set of names to keep in step with `hints.md`. _(the agent's choice, 2026-11-15)_
- **`reveals` written by hand in the hints:** each line lists after its `Mentions` the IDs it is meant to give away (`Reveals:`), rather than `compile` guessing them from step order, since players choose the order. _(the agent's choice, 2026-11-15)_
- **Several Alts per rung, each with its `when`:** prepared hints hold more than one Alt for a step, each replacing one named rung in one situation. _(the agent's choice, 2026-11-15)_
- **L4 stays in the dossier:** `compile` takes level 4 from the dossier's `L4 as spoken`, so `hints.md`, which the blind check reads, never holds an answer; the Spanish copy holds it as `L4`. _(the agent's choice, 2026-11-15)_
- **A bundle's baseline marks:** a knowledge entry is `known` in the bundle only when `knowledge.md` marks it `known`; `revealed` counts as `unknown`, since it records what one terminal session gave away rather than what the players brought. _(the agent's choice, 2026-11-15)_
- **Names per language, art as a drawn plan:** the map's name is stored in both languages, since in-game names differ by language, and its row shows one of three drawn plans chosen in the bundle's `art`, since no game's art goes on the site. The keys stay `teal`, `rust` and `furnace` from the first take's tinted silhouettes, standing for the boards' Harrow Station, Saltmarsh Asylum and Kessel Works plans. _(the agent's choice, 2026-11-15)_
- **The radio log look:** the owner found the first boards "very AI", so the site was redrawn as the group's radio log (transcript rows, dispatch slips, survey sheets, condensed type and five flat inks on paper), which replaces the first take. _(owner, 2026-11-15)_
- **A map's label is its game:** the boards label the made-up maps "Sample"; a published map that is not the test map shows its `game` instead, as the bundle holds no other short line about it. _(the agent's choice, 2026-11-15)_
- **A rung's `reveals`:** the discovery lets a rung mention an unknown thing when it is the rung meant to reveal it; the bundle says which rung that is with `reveals`, next to `mentions`. _(the agent's choice, 2026-11-15)_
- **Versions numbered per map, deduplicated by digest:** the SHA-256 of the bundle's JSON with sorted keys, so key order in the file never makes a new version. _(the agent's choice, 2026-11-15)_
- **Map rows without Start a run yet:** the boards draw it on every map's row, but a button that does nothing until runs exist would be a dead control; it comes with runs. _(the agent's choice, 2026-11-15)_ It came with runs on 2026-11-15.
- **Several local members:** `DEV_USER_ID` takes a list and each browser picks one of them, so a Claude-run check can be two members of one run; it exists only where `DEV_USER_ID` is set, never in production, which keeps Discord through the root as the DJ panel does. _(owner, 2026-11-15)_
- **The player picks the map:** a run is started from the map the players are playing, picked from the maps list as the boards draw it. _(owner, 2026-11-15)_
- **Runs stay open:** there is no way to close or end a run. _(owner, 2026-11-15)_
- **Knowledge follows the people:** a run's marks start from the bundle's baseline and the starter's earlier runs on the map, and each member who joins adds what their own earlier runs on it knew, so the marks are never lowered by who joins. _(the agent's choice, 2026-11-15)_
- **One link per run:** `/runs/<id>` is both the run and its join page, chosen by whether the reader is in it, so a link sent to a friend opens the run sheet the boards draw. _(the agent's choice, 2026-11-15)_
- **Ladders by handle:** the model sees a ladder as `s<n>` or `s<n>p<m>` from the bundle's order rather than its step's title, since titles name things the players may not know. _(the agent's choice, 2026-11-15)_
- **More in code first:** a card's More gives the next rung without a model call when the knowledge marks allow it, so it is instant and deterministic, and goes to the model only when they do not; an Alt is chosen by the model from what the players said in the chat. _(the agent's choice, 2026-11-15)_
- **The answer is asked for in words:** More never gives level 4; the model gives it only with `answer` set, when the players asked for it in the chat, as the skill's "Level 4 only when they clearly ask for the answer". _(the agent's choice, 2026-11-15)_
- **Marks from the players' words:** `mark_known` takes what the players said and code matches it against the knowledge names and the members' recent lines, so the model needs no list of unknown entries to mark one and cannot mark one the players never named. _(the agent's choice, 2026-11-15)_
- **Sentence-by-sentence streaming:** Cari's words reach the asker a sentence at a time rather than token by token, so a sentence naming an unknown entry is dropped before anyone reads it. _(the agent's choice, 2026-11-15)_
- **One reply at a time per run:** a lease on the run's row, held up to 60 seconds, waited on up to 30 (a line still waiting then gets no reply) and released only by the reply that took it, keeps two members' questions from getting two rungs of one ladder at once; Neon's pooled connections rule out a session advisory lock. _(the agent's choice, 2026-11-15)_
- **A card per reply:** a hint asked for in the chat comes on a new card under Cari's line, and More adds the next rung to the card it was pressed on, as the boards draw it. _(the agent's choice, 2026-11-15)_
- **The machine API is Claude's:** the token and routes first named "admin" are `CLAUDE_TOKEN` and `/api/claude/`, since only Claude uses them, from the terminal, to publish bundles and later to read and watch runs and step in as Cari; what they write is attributed to Claude. A browser admin like pkmn's (`npm run admin:create`, `/admin`) is not wanted now. _(owner, 2026-11-15)_
- **Attribution as a column:** a bundle version's `published_by` is a column that only ever holds `claude`, set by the route rather than defaulted by the database, so a later writer through another path has to name itself. _(the agent's choice, 2026-11-15)_
- **Neon from the Vercel Marketplace, without its variables:** the Neon organization is managed by Vercel and refuses a project made with `neonctl`, so the `zombies` project comes from the integration with `--no-connect`, and `DATABASE_URL` is set by hand per environment with `sslmode=verify-full`, as pkmn's table has it, rather than the integration's own variables. _(the agent's choice, 2026-11-15)_
