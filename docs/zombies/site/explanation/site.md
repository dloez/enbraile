# The Zombies Site

The site in `zombies/site/`, for `zombies.enbraile.vip`, where the group will start runs on a map and talk to the coach, Cari. Today it lists the maps Claude has published, and members start or join a run on one and talk in its shared chat, where Cari answers with the prepared hints and follows their progress, holds when no prepared line fits, and takes the group's revisions and ratings for Claude; the watch loop comes next ([Zombies Coach](../../../work-in-progress/zombies-coach/discovery.md)). Its look is in the [Site Design System](../reference/design-system.md).

## How It Is Built

It mirrors the [DJ panel](../../../dj/panel/explanation/panel.md): a Vite + React page, and one Hono function, `api/index.ts`, holding every route in `api/_lib/app.ts`. A signed-out reader is sent to the [root site](../../../home/site/explanation/site.md) and back: the function reads the session from the root's `/api/me` with the reader's cookie, so the site keeps no sign-in tables of its own. Locally, `DEV_USER_ID` stands in for a session: it holds a comma-separated list of members, each `<id>` or `<id>:<name>`, and `GET /api/dev/sign-in/<id>` sets a cookie that makes that browser one of them (the first one otherwise), so one machine can be two members of one run. The route answers 404 wherever `DEV_USER_ID` is unset, as it is on every Vercel deployment. The chrome is in English or Spanish, following the reader's `lang` cookie as the other sites do.

Maps live in their own Postgres database, never pkmn's, through Drizzle with `pg` as in [the pkmn site](../../../pkmn/site/explanation/site.md); the migrations in `drizzle/` run in the Vercel build. Its tables:

| Table | Holds |
|-------|-------|
| `maps` | One row per published map, keyed by game and map slug, with its latest version |
| `bundle_versions` | Every published bundle, numbered per map, with the SHA-256 of its canonical JSON and who published it, always `claude` |
| `runs` | One row per run: its map, the language Cari speaks, who started it, when Cari last asked the round, and the lease that lets one of Cari's replies run at a time |
| `run_members` | Each time a person joined a run, with when they left it; a unique index over the rows not left keeps a person in one run at a time |
| `messages` | The run's chat, each line from a member or from Cari, and its `kind`: `chat`, a member's `revision`, or Cari's `ack` of one |
| `run_knowledge` | The knowledge entries known in a run; an entry without a row is unknown |
| `hint_cards` | A hint card: the ladder it belongs to (a step, or one of its parts) and the Cari line it hangs under |
| `deliveries` | Every rung given, in order: its card, ladder, rung, Alt, level, the wording as delivered, its `mentions` and `reveals`, the bundle version and who asked |
| `run_steps` | A run's progress, never shown to players: each step or part the players started or finished, and when Cari told them a blocked step was not possible yet |
| `heads_ups_given` | Each heads-up Cari gave in a run, so none is given twice |
| `gaps` | Each time Cari held: the line asked, what the model said it was about, the holding line said, the bundle version, and the run's marks, open ladders, done steps and last lines at that moment |
| `feedback` | Each revision (its text, its message and the Cari line it refers to, with that line's card and newest rung) and each member's rating of a card (`obvious`, `right` or `vague`, one per member per card, the newest rung it was given on) |
| `coach_calls` | Every Claude call: model, tokens, latency, stop reason, refusal and its category, the rules code caught the model breaking, and any error |

## Map Bundles

A bundle is everything the live coach will need about one map, as one JSON document checked by the zod schema in `shared/bundle.ts`: the map's name in each language, which drawn plan stands for it, the knowledge entries with their `known` or `unknown` marks, the steps (`requires`, conditions, `optional`, the `onSuccess` line, the ladder, part ladders and heads-ups), the map's own calibration notes, and the dossier and sources as the durable copy. Every rung, each of its Alts (with `when` it replaces the rung) and every `onSuccess` line carries its wording in Spanish and English, the knowledge entries it `mentions`, which must already be known, and those it `reveals`; a heads-up carries its `mentions` only. The schema rejects a `mentions`, `reveals` or `requires` that names nothing, and repeated IDs.

A real map's bundle is not written by hand: `npm run compile -- <dir>` builds it from the files the ee-coach skill prepares in that map's dir ([Research and dossier building → Compile and publish](../../../../.claude/skills/ee-coach/references/research.md#4-compile-and-publish)) and writes `<dir>/bundle.json`. It reads `map.json` (the names and art plan), `hints.md` and `hints.es.md` paired line by line, the `L4 as spoken` and `Conditions` of each step in `dossier.md` (each indented `- ` item one condition, an indented line without one joined to the item above), `knowledge.md`, the map's `calibration.md` and every file under `sources/`, and checks what the schema cannot: that both languages hold the same lines with the same IDs, that a line reveals only what it mentions, and that no card text carries a step, hint or level number. Its messages name a file and line or a step and rung, never the text, and its summary is counts only, so its output can be quoted where the players read.

`npm run publish -- <dir>` reads `<dir>/bundle.json`, checks it, and sends it to `PUT /api/claude/maps/<game>/<map>` with `CLAUDE_TOKEN`. The function stores it as a new version, published by `claude`, unless its digest equals the latest one's, so publishing the same bundle twice leaves one version; an older bundle published again becomes the newest version, which is how a map is reverted. Real maps' bundles stay in the gitignored `zombies/maps/<game>/<map>/` ([Repository Layout](../../../general/explanation/repository-layout.md#decisions)); the one committed bundle is the made-up test map in `zombies/site/test-map/`, Harrow Station.

`/api/claude/` is the site's machine API, and it is Claude's: only Claude Code calls it, from the terminal, and every route under it answers 403 to any request without `CLAUDE_TOKEN` as its bearer token, whatever cookie it carries. What it writes is recorded as Claude's, as `published_by` is on a bundle version; the watch stream and step-ins still to come will join it under the same token and carry the same attribution.

`GET /api/claude/runs` lists every run with its map, language, starter, members, when it started and last spoke, and its counts of lines, rungs, gaps and feedback. `GET /api/claude/runs/<id>` returns the whole run for a debrief: the run, every membership, every line with its `kind`, the cards and every rung delivered, the feedback, the gaps, the marks known (with their names and when) and those still unknown, the progress in `run_steps`, the heads-ups given and every Claude call. `POST /api/claude/runs` imports a run coached from the terminal: the map, the language, the members with their Discord IDs (the first is the starter), the knowledge entries known, every rung given in order (its step or part, rung and Alt, and who asked), each step or part started, done or told blocked, and the heads-ups said. It checks every handle and rung against the latest bundle, that no Discord ID is listed twice and that each ladder's rungs come in order, and answers with the issues, by ID and position only, if any fails; otherwise it creates the run with each member moved into it, one card per ladder under a fixed Cari line ("De la sesión anterior." or "From the last session.") holding that ladder's rungs in the bundle's wording for the run's language, the marks (the bundle's baseline, the entries listed, and what every rung given mentions and reveals), the progress, with every step a done step `requires` done too as `record_progress` does, and the heads-ups, all at the moment of the import. `npm run import -- <dir> <name>=<discord id> ...` sends the dir's gitignored `import.json`, with each member's Discord ID, which a subagent writes from the map's `session.md` and `knowledge.md`, and prints the run's ID and counts. `npm run runs` prints the list, with no hint text in it; `npm run runs -- <id>` writes the whole run to the gitignored `zombies/maps/<game>/<map>/runs/<id>.json` and prints only its counts, since the log holds rungs and the gaps name what the players asked.

The maps page reads `GET /api/maps`, which returns each map's game and map IDs, its names, its `art` plan key, test flag and version and nothing else from the bundle, so no solution reaches a browser. The same reply carries each map's open runs and the reader's own run. A map's view, `/maps/<game>/<map>`, reads the same reply and shows that one map, so it needs no route of its own; every screen outside a run puts the reader's own run in the header as a "Your run" pill that leads back to it.

## Runs

Each map's row on the maps page opens the map's view, which lists its open runs and holds Start a run with the language Cari speaks inline (Spanish unless they pick English): `POST /api/runs`. Anyone signed in can join an open run with one tap on its row there, or from its link, `/runs/<id>`, which shows the join view to a reader not in it and the run to a member (`POST /api/runs/<id>/join`); a run's "Copy link" gives that link. A person is in one run at a time, so starting or joining a run leaves the one they were in, which a line under the actions says, without a step to confirm it. Nothing closes or ends a run, not even its last required step done: every run stays on its map's row, even once everyone has left it, and can be joined again.

A new run's knowledge marks are the latest bundle's `known` entries plus every entry known in the starter's earlier runs on that map (an imported run takes the terminal's marks instead, as above); each member who joins adds what was known in their own earlier runs there.

The run page polls `GET /api/runs/<id>/messages?after=<last id>&rungsAfter=<last rung id>` every 2 seconds for new lines, the current members and every hint card that gained a rung or arrived with a new line, each card carrying its rungs' wording and whether it shows More. `POST /api/runs/<id>/messages` adds a member's line and answers with Cari's reply as it is spoken. Both answer 403 to anyone not in the run.

## Revisions and Ratings

A line is a revision when its text starts with `REVISION:` (or `Revisión:`, in any case) or when it is sent with the composer's Revision toggle pressed, as the `run-revision` boards draw it; the mark is dropped from the stored text. A revision never reaches the model: it is stored with `kind` `revision`, a `feedback` row records it with the last Cari line before it that was not an acknowledgement (and that line's card and newest rung, when it has one), and Cari answers at once with a fixed line in the run's language, "Anotado, gracias." or "Noted, thanks.", stored as an `ack`, in the same streamed reply shape as any other but with no Claude call. The chat shows a revision with its tag and "re: Cari time · for Claude". Every line whose `kind` is not `chat` is left out of the conversation the model reads.

Every card's foot holds the three ratings (too obvious, right, too vague) in Cari's language. A tap is `PUT /api/runs/<id>/cards/<card>/feedback`, which keeps one rating per member per card, the latest, with the card's newest rung at that moment; each reader's poll returns their own rating on each card. Ratings never reach the model either. Claude reads both from the run read above and folds them into calibration and the hints in the ee-coach debrief.

## Cari

Cari is Claude, `COACH_MODEL` (Haiku 5.5, `claude-haiku-5-5`, unless set) with `ANTHROPIC_API_KEY`, called by the function on every member's line; without a key she stays silent. The model never writes a hint: it acts through six tools, and code decides what each may do.

- **`give_hint`** hands over the next rung of one ladder, or one of that rung's Alts. Code gives only a rung whose `mentions` are all known in the run (its `reveals` may still be unknown, since it is the line meant to give them away), one per reply, level 4 only when the model says the players asked for the answer, and records the delivery and adds the rung's `mentions` and `reveals` to `run_knowledge` in the same transaction.
- **`mark_known`** takes the players' words; code marks known every unknown entry whose name, in either language and without its article, appears both in them and in a member's line among the last 24, so the model cannot mark something only a rung named.
- **`record_progress`** records a step or part as started or done, by its handle. A step marked done marks every step it `requires` done too, since they had to come first. On a step done, code marks known what its `onSuccess` line mentions and the players named in the chat, says that line when all it mentions is known, and hands over on a card the first rung of a ready step, the one the model names with `next` or else the first in the bundle's order; the model passes `quiet` only when the players said what they are doing next. A part done just closes that part's ladder.
- **`heads_up`** says one of an open step's heads-ups, word for word, once per run.
- **`hold`** is for a question no listed hint covers. Code says one of three prepared holding lines in the run's language, in turn by how many gaps the run has, records a gap with the model's few words on what was asked and the run's state, and ends the reply; it is refused after a hint in the same reply. Claude writes and checks the missing line from the gap, and publishes it ([Zombies Coach → Feedback and the watch loop](../../../work-in-progress/zombies-coach/discovery.md#feedback-and-the-watch-loop)).
- **`ask_round`** adds the run's fixed question about the round to the reply, at most once every 10 minutes and never in a reply that gives a hint.

The prompt is a system prompt distilled from the ee-coach skill's session rules, then the run's state, sorted the way the skill keeps its open threads:

- **Open threads:** each ladder the players started or were given a rung of, with the rungs given and the next rung and Alts code would allow.
- **Ready:** the first rung of each ladder not opened yet whose step's `requires` are all done and whose `mentions` are known, never an optional step's.
- **Optional, not started:** listed only so the model can record one the players start themselves; code refuses any rung of an optional step until then.
- **Blocked:** steps whose `requires` are not all done, each listed once the players have opened it or, for a required step, once its title names nothing unknown.
- **Done**, and the heads-ups and conditions of the open threads.

A step or part is named by its title only when the title names no unknown entry, so the model can tell which one the players are talking about without learning what they have not met; otherwise it is only its handle. An Alt, heads-up or condition whose text names an unknown entry is left out. Ladders are named by handles (`s2`, `s2p1`), never by their step's title, so the dossier and the titles stay out of it, and an unknown entry's name reaches the model only inside a rung meant to reveal it, which is one of the rungs it may give. The last 24 lines of the chat are the conversation, with each card's rungs under Cari's line in brackets.

A blocked step gets no hint of its own. The first time the model asks for one, code says a fixed line in the run's language, the skill's "this isn't budging… maybe it isn't the moment", and records it; each later ask hands over the next rung of the step that is missing, followed down its own `requires` to one that is ready, so the ladder aimed at the blocker is made of that step's checked rungs and names nothing they lack before those rungs do.

Her own words are streamed to the asker sentence by sentence as newline-delimited JSON, while the run page shows her row "transmitting" with the blinking caret; a sentence naming an unknown entry, holding brackets, or repeating a line code said or a rung given is dropped and recorded as a violation instead. When the reply ends, her line and its card are stored together and every member's next poll shows them. When the reply fails before she has said anything or given a card (the call to Claude, or the turn itself throwing), the stream ends with a `failed` event, so the asker's page says she did not answer instead of falling silent; a refusal stays silent. A card's More asks `POST /api/runs/<id>/cards/<card>/more`, which gives the ladder's next rung onto the same card in code, without a model call, when that rung is allowed; when it is not, the model is told More was pressed and chooses an Alt or asks what they see. More shows only on the newest card of its ladder, never when the next rung is level 4, and never once its step or part is done; a poll after a step is done sends that step's cards again without it.

Each Claude call is a row in `coach_calls`, and each rung a row in `deliveries`, so a run's whole hint history can be read back against its marks.

## Hosting

Vercel serves the site from the owner's Hobby team as the project `enbraile-zombies`: the Vite build's static `dist/` and the API as a Vercel Function (`api/index.ts`) in the same project, as pkmn's and the DJ panel's are. `vercel.json` runs the function in Frankfurt (`fra1`), beside its Neon database (`aws-eu-central-1`), and rewrites every path but `/api/` and `/assets/` to `/index.html`. The database is the Neon project `zombies`, its own and never pkmn's, with a `main` branch for production and a `dev` branch for previews. The `zombies-site.yml` workflow deploys pushes to `main` touching `zombies/site/` to production, and other branches' pushes as previews, which Vercel's Deployment Protection keeps to the team ([How to Deploy the Vercel Projects](../../../general/how-to/deploy-vercel-projects.md)). The function also reads `ANTHROPIC_API_KEY` and `COACH_MODEL`, set in Production. `zombies.enbraile.vip` is on the project's domains and has, since the owner added it on 2026-11-15, a DNS-only (grey-cloud) `CNAME` to the Vercel target in the `enbraile.vip` zone on the owner's Cloudflare account. It is DNS-only for the reason pkmn's is: Cloudflare's proxied IPs are blocked by Spanish ISPs during LaLiga matches ([The pkmn Site → Decisions](../../../pkmn/site/explanation/site.md#decisions)). The root site lists the domain in its `trustedOrigins`, so sign-in returns to it. Setting it up is in [How to Run and Deploy the Site](../how-to/run-and-deploy-the-site.md#9-set-up-production-once).

## Decisions

- **No numbers, no step list, the UI is never a hint:** no step or hint numbers anywhere (the terminal's "Step 5 · hint 2/4" is not shown), no list of steps, and no buttons or suggestions that tell players what to try. _(owner, 2026-11-15)_
- **Hints as cards:** one shared chat with Cari, where hints arrive as cards with a generic "more" control and the three feedback controls (too obvious, right, too vague); a level-3 zone shows under its card. _(owner, 2026-11-15)_
- **Cari's voice only:** no chimes or clips on a new hint, since a cue would itself carry meaning. _(owner, 2026-11-15)_
- **One `bundle.json` per map dir:** `publish` takes the dir that holds a map's files, and `compile` writes the bundle there. _(the agent's choice, 2026-11-15)_
- **Bundle IDs from the prepare files' numbers:** steps become `step-<n>`, a step's part ladders `part-<n>` in order, and knowledge entries their `K` IDs in lowercase, so the bundle needs no second set of names to keep in step with `hints.md`. _(the agent's choice, 2026-11-15)_
- **`reveals` written by hand in the hints:** each line lists after its `Mentions` the IDs it is meant to give away (`Reveals:`), rather than `compile` guessing them from step order, since players choose the order. _(the agent's choice, 2026-11-15)_
- **Several Alts per rung, each with its `when`:** prepared hints hold more than one Alt for a step, each replacing one named rung in one situation. _(the agent's choice, 2026-11-15)_
- **L4 stays in the dossier:** `compile` takes level 4 from the dossier's `L4 as spoken`, so `hints.md`, which the blind check reads, never holds an answer; the Spanish copy holds it as `L4`. _(the agent's choice, 2026-11-15)_
- **A bundle's baseline marks:** a knowledge entry is `known` in the bundle only when `knowledge.md` marks it `known`; `revealed` counts as `unknown`, since it records what one terminal session gave away rather than what the players brought. _(the agent's choice, 2026-11-15)_
- **Names per language, art as a drawn plan:** the map's name is stored in both languages, since in-game names differ by language, and its row shows one of three drawn plans chosen in the bundle's `art`, since no game's art goes on the site. The keys stay `teal`, `rust` and `furnace` from the first take's tinted silhouettes, standing for the boards' Harrow Station, Saltmarsh Asylum and Kessel Works plans. _(the agent's choice, 2026-11-15)_
- **The radio log look:** the owner found the first boards "very AI", so the site was redrawn as the group's radio log (transcript rows, dispatch slips, survey sheets, condensed type and five flat inks on paper), which replaces the first take. _(owner, 2026-11-15)_ The third take replaced its look and kept its identity, below.
- **A map's label is its game:** the boards label the made-up maps "Sample"; a published map that is not the test map shows its `game` instead, as the bundle holds no other short line about it. _(the agent's choice, 2026-11-15)_
- **A rung's `reveals`:** the discovery lets a rung mention an unknown thing when it is the rung meant to reveal it; the bundle says which rung that is with `reveals`, next to `mentions`. _(the agent's choice, 2026-11-15)_
- **Versions numbered per map, deduplicated by digest:** the SHA-256 of the bundle's JSON with sorted keys, so key order in the file never makes a new version. _(the agent's choice, 2026-11-15)_
- **Map rows without Start a run yet:** the boards draw it on every map's row, but a button that does nothing until runs exist would be a dead control; it comes with runs. _(the agent's choice, 2026-11-15)_ It came with runs on 2026-11-15.
- **Several local members:** `DEV_USER_ID` takes a list and each browser picks one of them, so a Claude-run check can be two members of one run; it exists only where `DEV_USER_ID` is set, never in production, which keeps Discord through the root as the DJ panel does. _(owner, 2026-11-15)_
- **The player picks the map:** a run is started from the map the players are playing, picked from the maps list as the boards draw it. _(owner, 2026-11-15)_
- **Closing a run is not built yet:** there is no way to close or end a run, and a run never ends by itself, not even when its last required step is done. _(owner, 2026-11-15)_
- **A run ends only when the players say so:** when closing is built, a run ends only when the players ask for it and confirm. _(owner, 2026-11-15)_
- **Progress kept in `run_steps`, never shown:** what the players started and finished lives on the run for the coach and later for debriefs, and no route a browser calls returns it, since a list of threads would be a hint. _(the agent's choice, 2026-11-15)_
- **The L1 after a step done is chosen in code:** `record_progress` hands it over itself, from the ready steps, so a step done always gets its `On success` line and an L1 in the same reply even when the model forgets, and an optional step is never among them. _(the agent's choice, 2026-11-15)_
- **Titles only when they name nothing unknown:** a step's title reaches the model once the players have met everything it names, so it can record a step they report without seeing what they have not found. _(the agent's choice, 2026-11-15)_
- **Done implies its `requires`:** a step reported done marks the steps it requires done, since the bundle's `requires` say they had to come first. _(the agent's choice, 2026-11-15)_
- **The blocked ladder from prepared lines:** the skill's blocked-thread ladder has no lines of its own in the bundle, so its first rung is one fixed line per language in code and the rest is the missing step's own ladder, which keeps every word prepared and checked. _(the agent's choice, 2026-11-15)_
- **`On success` learns what the players named:** a step done marks known the entries its `On success` line mentions that a member named in the chat, so the line is said when the players reported it in their own words even if the model did not mark them first. _(the agent's choice, 2026-11-15)_
- **Code drops repeats:** a sentence of the model's that repeats an `On success` line, a fixed line or a rung already given is dropped, since Haiku echoed lines code had just said. _(the agent's choice, 2026-11-15)_
- **Knowledge follows the people:** a run's marks start from the bundle's baseline and the starter's earlier runs on the map, and each member who joins adds what their own earlier runs on it knew, so the marks are never lowered by who joins. _(the agent's choice, 2026-11-15)_
- **One link per run:** `/runs/<id>` is both the run and its join page, chosen by whether the reader is in it, so a link sent to a friend opens the join view the boards draw. _(the agent's choice, 2026-11-15)_
- **Ladders by handle:** the model sees a ladder as `s<n>` or `s<n>p<m>` from the bundle's order rather than its step's title, since titles name things the players may not know. _(the agent's choice, 2026-11-15)_
- **More in code first:** a card's More gives the next rung without a model call when the knowledge marks allow it, so it is instant and deterministic, and goes to the model only when they do not; an Alt is chosen by the model from what the players said in the chat. _(the agent's choice, 2026-11-15)_
- **The answer is asked for in words:** More never gives level 4; the model gives it only with `answer` set, when the players asked for it in the chat, as the skill's "Level 4 only when they clearly ask for the answer". _(the agent's choice, 2026-11-15)_
- **Marks from the players' words:** `mark_known` takes what the players said and code matches it against the knowledge names and the members' recent lines, so the model needs no list of unknown entries to mark one and cannot mark one the players never named. _(the agent's choice, 2026-11-15)_
- **Sentence-by-sentence streaming:** Cari's words reach the asker a sentence at a time rather than token by token, so a sentence naming an unknown entry is dropped before anyone reads it. _(the agent's choice, 2026-11-15)_
- **One reply at a time per run:** a lease on the run's row, held up to 60 seconds, waited on up to 30 (a line still waiting then gets no reply) and released only by the reply that took it, keeps two members' questions from getting two rungs of one ladder at once; Neon's pooled connections rule out a session advisory lock. _(the agent's choice, 2026-11-15)_
- **A card per reply:** a hint asked for in the chat comes on a new card under Cari's line, and More adds the next rung to the card it was pressed on, as the boards draw it. _(the agent's choice, 2026-11-15)_
- **The machine API is Claude's:** the token and routes first named "admin" are `CLAUDE_TOKEN` and `/api/claude/`, since only Claude uses them, from the terminal, to publish bundles and later to read and watch runs and step in as Cari; what they write is attributed to Claude. A browser admin like pkmn's (`npm run admin:create`, `/admin`) is not wanted now. _(owner, 2026-11-15)_
- **No tag in the header:** the header holds the wordmark, the language switch and the name chip; the "Radio log · enbraile.vip" tag is gone from the site, the boards in `zombies/site/design/` and the design-system doc. _(owner, 2026-11-15)_ Since the third take the header also holds the "Your run" pill outside a run.
- **The third take:** the owner found the radio log's flow awkward and its UI clumsy and hard to read, and asked for clickable map rows and a remake by Claude design; the canvas's "Third take" boards replace the radio log's: every map row opens a map view with its open runs and Start a run, a shared link lands on the join view, a "Your run" pill leads back to the reader's run, and the look is a warm dark theme with Atkinson Hyperlegible Next body text, keeping the run as a log and hints as dispatch slips. _(owner, 2026-11-15)_
- **The map view reads `/api/maps`:** `/maps/<game>/<map>` takes its map out of the maps page's reply rather than a route of its own, since that reply already holds the map, its open runs and the reader's run and is small; a map not in it shows "No such map on file." _(the agent's choice, 2026-11-15)_
- **Join in one tap from the map view:** a run's row on the map view joins it at once and opens the run, as the board's row links straight to the run, so picking a map and joining is two taps; the join view is for a shared link. _(the agent's choice, 2026-11-15)_
- **Several open runs on a map row:** the boards draw a row with one run or none; with more, the row says how many are open (and "you're in it" when one is the reader's), and the map view lists them. _(the agent's choice, 2026-11-15)_
- **A failed reply says so:** a reply whose Claude call failed before Cari said anything ends with a `failed` event and the run page offers to try again, rather than a silent Cari the players cannot tell from a choice to stay quiet. For a line, trying again posts the line a second time, since a run has no way to ask for a reply without a line; for More, it presses More again. _(the agent's choice, 2026-11-15)_
- **One spacing scale:** every padding, margin and gap in the site's CSS is a step of a 4px scale (`--sp-1` to `--sp-20`), but for the few baseline offsets the [design system](../reference/design-system.md#spacing) names; the boards' in-between values (6, 10, 14, 18, 22px) move to the nearest multiple of 8, so the built screens can sit a few pixels off the boards. _(the agent's choice, 2026-11-15)_
- **Titles fit their longest word:** a map's name in a large condensed title shrinks until its longest word fits its column instead of breaking mid-word, since names differ by language and the published maps' Spanish names are longer than the boards' made-up ones. _(the agent's choice, 2026-11-15)_
- **Attribution as a column:** a bundle version's `published_by` is a column that only ever holds `claude`, set by the route rather than defaulted by the database, so a later writer through another path has to name itself. _(the agent's choice, 2026-11-15)_
- **Holds from prepared lines:** a hold says one of three fixed lines per language, chosen in code, rather than words of the model's, so the line a gap gets is never improvised (her own words around it still pass only the sentence filters above); the line may ask what they see, as the discovery allows. _(the agent's choice, 2026-11-15)_
- **Revisions as lines of the chat:** a revision is stored in `messages` with its own `kind`, so it shows in the log where the boards draw it, and in `feedback`, which carries what it refers to; the history the model reads takes `chat` lines only. _(the agent's choice, 2026-11-15)_
- **A revision refers to Cari's last line:** a revision has no picker for the line it is about, so it refers to the last line Cari said before it that was not an acknowledgement, and Claude reads the log around it. _(the agent's choice, 2026-11-15)_
- **The toggle lets go after a send:** the Revision toggle turns off once its revision is sent, so the next line goes to Cari as play unless it is pressed again. _(the agent's choice, 2026-11-15)_
- **One rating per member per card:** a member's later tap replaces their earlier one, and the rating records the card's newest rung, so a card that grew under More is judged on what it said last. _(the agent's choice, 2026-11-15)_
- **Runs read to a gitignored file:** `npm run runs -- <id>` writes the run under the map's gitignored dir and prints counts, since the log holds hint text the players may read off the terminal. _(the agent's choice, 2026-11-15)_
- **An import is the terminal's record:** an imported run's marks are the bundle's baseline, the entries the session's `knowledge.md` marks known or revealed and what its rungs mention and reveal, without what its members knew in earlier runs on the map, so the run reads back exactly as the terminal left it; members who join later still add their own. _(the agent's choice, 2026-11-15)_
- **Imported rungs on one card per ladder:** the terminal kept no chat the site could show, so each ladder's rungs given there are one card under a fixed Cari line, as if grown with More, and only lines from the bundle are imported; a hint the terminal improvised has no rung to import and is folded into the hints at the debrief first. _(the agent's choice, 2026-11-15)_
- **Neon from the Vercel Marketplace, without its variables:** the Neon organization is managed by Vercel and refuses a project made with `neonctl`, so the `zombies` project comes from the integration with `--no-connect`, and `DATABASE_URL` is set by hand per environment with `sslmode=verify-full`, as pkmn's table has it, rather than the integration's own variables. _(the agent's choice, 2026-11-15)_
