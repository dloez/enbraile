# The Zombies Bot Module

The coach's voice in the group's Discord call: a module of the [Enbraile bot](../../../home/bot/explanation/bot.md) with its code in `zombies/bot/`. It brings the bot into a run member's voice channel, hears the attempt's wake word («bebé …» or «richtofen …») and passes it to the [site](../../site/explanation/site.md), which answers as the speaker's run, speaks the answer back, and sends the site everything else said in the call for the run to keep. The bot is only the interface: it holds no run state and calls no model ([The Zombies Site → Decisions](../../site/explanation/site.md#decisions), "The site is the brain, the bot only an interface").

## How It Works

The module (`src/index.ts`) brings the `/coach` command and the routes; the call itself is in `src/call.ts`.

- **Joining:** `/coach` in Discord, or the site's `POST /zombies/join` with the member's `userId` and their attempt's `voice`, holds the host's voice connection for `zombies` in the channel that member is in, with `listen`, so the bot hears the call. `/coach` asks the site for the voice with `POST <ZOMBIES_URL>/api/voice/coach`, and its reply names the attempt's character and wake word ("Richtofen is in your channel. Say «richtofen» …"). Joining answers `{ channelId }`, or 409 with `{ error }` set to `notInVoice`, `noAccess` (the bot's role cannot view, connect or speak there) or `full`. `/coach` gives the same outcome as an ephemeral reply in the user's language. If the DJ is playing in another channel, joining moves the bot, as any lease does.
- **Looking:** `GET /zombies/voice?userId=` answers `{ channel, coach }`: the member's voice channel (`id`, `name`, `canJoin` and the `reason` it cannot) or `null`, and the channel the module holds or `null`, so the site can decide whether to offer bringing the coach in.
- **Naming:** `POST /zombies/names` with `{ ids }`, up to 50 Discord IDs, answers `{ names, avatars }`: each ID that is a member of the server mapped to its current server display name, and to its avatar's 128px WebP URL on `cdn.discordapp.com` (the server avatar, else the account's; a member with neither is left out of `avatars`), fetched from Discord rather than the cache, since the bot gets no member updates; an ID it cannot find is left out of both. The site shows members by these names and avatars ([The Zombies Site → Attempts](../../site/explanation/site.md#attempts)).
- **Leaving:** `POST /zombies/leave` with `{ userIds }`, a run's members, drops the lease when the member who brought the coach in last is one of them, answering `{ ok: true }`, and otherwise answers 409 `{ error: "notInCall" }` and stays; the site sends it when an attempt closes ([The Zombies Site → Attempts](../../site/explanation/site.md#attempts)). The last person leaving the bot's channel drops the lease too; the bot stays if the DJ still holds it.
- **Hearing:** the module registers every character's wake word, «bebé» and «richtofen», with `hearing.onTrigger` once, at start. While it holds the call, each trigger is sent to `POST <ZOMBIES_URL>/api/voice` as `{ userId, text, word }`, with `INTERNAL_SECRET` as the bearer token; the site finds the speaker's run, answers there if the word wakes that run's character, and streams newline-delimited JSON back: a `voice` event, which the module holds, then a `say` event per sentence, then `done` ([The Zombies Site → Voice](../../site/explanation/site.md#voice)). Each sentence goes to `hearing.say` in that voice as soon as it arrives, without waiting for the next; the worker makes replies one at a time in the order asked ([The Voice Worker](../../../home/voice/explanation/voice.md)), so the first sentence plays while the next is made. An answer with no `voice` is silence. A request that fails or times out (25 s for the whole stream) before any sentence came, or an answer that named a voice and said nothing, is met with the line asking them to say it again of the character whose voice it holds, in Spanish, the group's language, since a wake word is always addressed to the coach ([The Zombies Site → Decisions](../../site/explanation/site.md#decisions)); a failure is logged, and the sentences already queued are still said.
- **Speaking for the site:** `POST /zombies/say` with `{ text, voice, userIds }` speaks a line the site posted without a wake word asking for it (Claude's step-in, a held question answered when a version lands): while the module holds the call and one of `userIds`, the run's members, is in its channel, it holds `voice` as a reply would and says `text` with `hearing.say` in it, a sentence at a time (split after `.`, `!`, `?` or `…`) so the first is heard while the rest are made, answering `{ ok: true }` at once without waiting for the speech; otherwise it answers 409 `{ error: "notInCall" }` and says nothing. A failed `say` is logged as `zombies say` ([The Zombies Site → Voice](../../site/explanation/site.md#voice)).
- **Holding the voice:** while it holds the call the module holds its attempt's voice with `hearing.hold("zombies", voice)`, from the moment it joins, so the worker loads it before the first wake word, and switches the hold when an answer names another voice, the attempt's having changed. It releases the voice when it leaves or loses the call. A voice the worker may not load (outside its `VOICES`) is not held and the reply is spoken in the worker's default; a voice still loading makes the `say` wait, and past the worker's limit it speaks in a loaded voice ([The Voice Worker → Voices](../../../home/voice/explanation/voice.md#voices)).
- **Keeping the call:** while the module holds the call it asks the host for transcripts with `transcripts.keep("zombies", true)`, and takes the request back when it leaves or loses the lease, so the bucket stores the call too when it is configured. Its `hearing.onTranscript` handler, registered once at start, sends each line said in the call, triggers included, to `POST <ZOMBIES_URL>/api/voice/transcript` as `{ userId, name, text, at, ms, broughtBy }`, `broughtBy` being the member who brought the coach in last, so the site can file a line from someone in no run under that member's run. A failed request is logged and the line is not sent again. The coach's own spoken lines are not sent, since its replies are already in the run's chat.

Every route sits behind the host's `INTERNAL_SECRET` ([The Enbraile Bot → How It Runs](../../../home/bot/explanation/bot.md#how-it-runs)). `ZOMBIES_URL` defaults to `https://zombies.enbraile.vip`; a local run against a local site sets it.

## Deploying

The module deploys with the host: see [The Enbraile Bot → Deploying](../../../home/bot/explanation/bot.md#deploying).

## Decisions

- **The site's address defaults to production:** the bot's cluster manifest in `dloez` needs no new variable, and a local run overrides it with `ZOMBIES_URL`. _(the agent's choice, 2026-11-15)_
- **A `voice` route beside `join`:** the site offers to bring the coach in only when a member is in a channel, and only the bot can see voice states. _(the agent's choice, 2026-11-15)_
- **The coach is not brought back after a bot restart:** the host keeps its leases only in memory, so a deploy drops it from the call and it stays out until someone brings it in again; that is acceptable, and the module keeps no record of the call it held. _(owner, 2026-11-16)_
- **Closing an attempt takes the coach out of the call, only if that attempt brought it in:** the coach otherwise stayed until everyone left the channel, since nothing on the site told it to go; the module holds one call for whichever run brought it last, so closing another attempt leaves it where it is. _(owner asked, the scope the agent's, 2026-11-18)_
- **The lease drops when the call empties,** since a listening lease left behind would keep the bot in an empty channel hearing nothing. _(the agent's choice, 2026-11-15)_
- **The chime on a wake word stays on** (the trigger's default `ack`): it only says the word was heard, which the voice tests asked for, not that a hint is new, so it is not one of the sound cues the site's "The coach's voice only" rules out ([The Zombies Site → Decisions](../../site/explanation/site.md#decisions)). _(the agent's choice, 2026-11-15)_ From 2026-11-17 each character answers its wake word with a short line of its own in its voice instead (three of a word or two each, «Mmm…», «A ver…», «Vale…» as Coach in `chatterbox` and «Hmm…», «Ach…», «Veamos…» as Richtofen, shortened on 2026-11-17 at the owner's ask so they play at once), and the bot's own "say that again" line, said when the site's answer holds nothing to speak, is one of three per character, as on the site, kept in `zombies/bot/src/call.ts` with the character, after the owner asked for something more natural than the ping. Like the chime it says only that the word was heard, never anything about the hints. Coach's lines are in `chatterbox` whatever voice the attempt chose. From 2026-11-17 a character whose voice is not loaded gets no acknowledgement at all rather than the chime, at the owner's ask. _(owner, 2026-11-17)_ _(owner asked, the lines and design the agent's, 2026-11-17)_
- **Each call line goes to the site as it is heard,** one request per sentence and none retried: sentences come seconds apart, and the bucket keeps the full call when it is configured. _(the agent's choice, 2026-11-15)_
- **A line from someone in no run goes to the run of whoever brought the coach in,** since a friend in the call who never opened the site is still part of the attempt. _(the agent's choice, 2026-11-15)_
- **Names fetched one by one, fresh:** `names` fetches each member from Discord with `force`, in parallel, since the host has no `GuildMembers` intent and so its member cache is never updated after a rename; the site's one-minute cache keeps the requests few. _(the agent's choice, 2026-11-16)_
- **A line is spoken only in its run's call:** the module holds one call and no run state, so `say` takes the run's current members and speaks only when one of them is in the channel it holds, rather than wherever the bot happens to be. _(the agent's choice, 2026-11-16)_
- **The site's answer is streamed, each sentence spoken as it comes:** the module says every `say` the moment it arrives instead of one joined reply, so the first words are heard while the coach is still writing; the language is the run's, chosen on the site. _(the agent's choice, 2026-11-15; streamed 2026-11-16)_
- **The bot learns the attempt's voice from the site, never keeps it:** the join carries it and every reply names it, so the bot holds no run state and a voice changed mid-attempt is held from its next reply. The voice is held for the whole call rather than per reply, since Richtofen takes 10–18 s to load and a reply waiting on it would be late. _(the agent's choice, 2026-11-16)_
- **The characters' names, wake words and repeat lines are listed in the module:** the bot image carries only `zombies/bot/`, so it cannot read the site's characters (`zombies/site/shared/voices.ts`); a new character is added to `call.ts` too, its repeat line copied from the site's Spanish one. _(the agent's choice, 2026-11-16)_
