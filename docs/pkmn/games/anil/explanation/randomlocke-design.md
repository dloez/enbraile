# Randomlocke Design

How Pokémon Añil v4.14 is turned into the group's Randomlocke: the mod that makes every new game start as the configured Randomlocke with no mode menus, the Gen 1–5 caps, and the eggs and the Showdown export it adds. It was designed with the owner in Wonder, together with the port of Wonder's tooling to Añil and the group's rules, and copied here without Wonder's agent, its players and wonder zips (Wonder: `docs/subsystems/harness/explanation/randomlocke-design.md`). The code is `pkmn/games/anil/src/anil/mod/` (the mod's preloaded Ruby, the allow-lists and the Showdown names), deployed by [`anil install`](runtime-design.md#deploy).

The rules as a player sees them are owned by [Series 1 Rules](../../../series/1/reference/rules.md); what the game was seen to do under the mod is owned by [Runtime → Randomlocke Mod](../reference/runtime.md#randomlocke-mod), [Runtime → Checks](../reference/runtime.md#checks), [Runtime → Packages](../reference/runtime.md#packages), and the game references they link ([Nuzlocke](../reference/nuzlocke.md), [Randomizer](../reference/randomizer.md), [Level Caps](../reference/level-caps.md), [Battle Mechanics](../reference/battle-mechanics.md)). This doc holds how the mod works, the configuration, and why each part is the way it is.

Code citations: `S/NNN_Name.rb` is a section of Añil's `Data/Scripts.rxdata`, and `P/<plugin>/<file>.rb` is a file of `Data/PluginScripts.rxdata`, in load order. `anil install` writes them to `game/extracted/<build>/scripts/` and `plugins/`. Two of the shipped `Plugins/` source folders were diffed against `PluginScripts.rxdata` on 2026-10-02 and are identical to it: `Plugins/Nuzlocke EX/`, the "Challenge Modes 1.0.2" plugin, and `Plugins/Modo Random/`, "Random Pokemon & Moves + Randomizer EX (Abilities)". The other folders were not compared.

## What the Mod Does

Every player plays the same packaged game, and nobody chooses options: the human players are not technical, so the mod sets everything up and they only run `Game.exe`. A new game from it starts with Añil's own randomizer and Challenge Modes Nuzlocke set to the owner's configuration, Completo difficulty, Set battle style and visible wild Pokémon off, all with no selection menus, plus the Gen 1–5 caps, no Mega Evolution, the official types, classic freeze and 16 eggs in a PC box. `anil install` deploys the same mod to a working copy ([Runtime Design → Deploy](runtime-design.md#deploy)). Every change is preloaded Ruby that patches the game once its plugins load; `Scripts.rxdata`, `PluginScripts.rxdata`, PBS and compiled data stay pristine ([Runtime Design → Game Modifications](runtime-design.md#game-modifications)).

## New-Game Setup

The mod in `pkmn/games/anil/src/anil/mod/` sets up every new game as follows. The facts it rests on are in [Runtime → Randomlocke Mod](../reference/runtime.md#randomlocke-mod).

- **Hooks:** `randomlocke.rb` is preloaded before the bridge, when there is one. At preload it sets the window title and installs three definition hooks: `PokeUpdater.singleton_method_added` (the three updater methods answer nil and log `updater call … skipped`), `DiscordAPI.method_added` (an empty `initialize`, so no `MiniFFI` binding is made) and `PluginManager.singleton_method_added`, which wraps `PluginManager.runPlugins`. Everything else is patched once `runPlugins` returns, because the plugins define what it patches. The hooks are the mod's, not the bridge's, so a copy without the bridge has them too.
- **After the plugins load:** the base self-check, then the patches below, then the Options entries `:battle_style` and `:salvajes_visibles_en_ow` removed from `MenuHandlers`, and `PokemonGlobalMetadata#randomlocke_version` added.
- **Where the setup runs:** `Interpreter#command_201` is wrapped. The intro's transfer from Map001 to Map104 is replaced by a transfer to Map217's destination, the bedroom (Map028 at 29,10, facing down), keeping the intro transfer's fade (Map217's own transfer has none) so the setup's screen changes happen behind it, and the setup runs at that moment, once, unless `$PokemonGlobal.randomlocke_version` is already set. That transfer comes after the last `pbTrainerName` and the rival's name, and nothing else in the game transfers to Map104 or Map217. Map104 and Map217 are never shown.
- **What the setup does:** switch 110; `battlestyle` 1; `salvajes_visibles_en_ow` 1; what Map217 would have done (running shoes, variables 76, 78 and 79, the menu enabled again, the player's opacity back to 255, the screen tone cleared); the challenge queued as in [Nuzlocke](#nuzlocke); `initialize_random_params(true)` for fresh randomizer caches, then the flags, `RandomizerConfigurator.gens=`, `RandomizerConfigurator.ability_mode=`, `randomizer_rules` in the shape the randomizer's own menu stores, and `generate_random_starters`; the TM-compatibility file rewritten from the fresh, empty table; the 16 eggs in box 50 ([Eggs](#eggs)); switch 34 (`Settings::NO_MEGA_EVOLUTION`) on ([Applying the Caps](#applying-the-caps)); the RULEBOOK added to the bag without the key-item scene; and `randomlocke_version` set to the mod's version, which marks the save.
- **The locks cover every copy, not only marked saves:** `PokemonSystem#battlestyle=` always stores 1 and `#salvajes_visibles_en_ow=` always stores 1, and the PC's `pbMostrarMenuCustomizacion` only says, in Spanish, that the modes are fixed and the rules are in the Libro de Reglas. The package is only ever the Randomlocke, so a save from a plain Añil install loaded into it is not a supported case.
- **The TM-compatibility file follows the save:** after every successful `Game.save` of a marked save with TM compatibility on, the in-memory table is written to the file for the save's slot.
- **Version and title:** `anil.mod.sources.VERSION` (1) is written into the generated `randomlocke_version.rb`; the title is "Pokémon Añil Randomlocke v1", and `pbSetWindowText(nil)` restores it instead of the game's title.
- **Self-check warning:** a mismatch is logged and shown with `print`, the message box Essentials also uses for its error reports, before the title screen.
- **The starter-region default:** the top-level `pbMostrarListaStarters` is aliased, and on a marked save the replacement sets switch 334 and variable 31 to the first region (Kanto, `[:BULBASAUR, :CHARMANDER, :SQUIRTLE]`), logs `randomlocke starter region set: Kanto`, then makes the new-game save. An unmarked save keeps the menu. Kanto, index 0, is the region EV29's own fallback uses, and index 1 is ruled out ([Forced by Evidence](#forced-by-evidence)).
- **The new-game save is made by the default:** the default is the first thing that runs in the bedroom after the setup, so it is where the save goes. It saves only while `$player.save_slot` is nil, refreshes Multi Save's slot list first (it caches the folder listing for a second), takes `get_new_manual_slot`, refuses if that file already exists, and calls `Game.save(slot)`, which sets the slot. So the mod's `Game.save` wrapper writes the slot's TM-compatibility file at once. The save is taken while Map028 EV18 is still running, so loading it resumes that event at the same command: the default runs again, saves nothing since the slot is set, and the event goes on to its PC message. It logs `randomlocke new game saved to <slot>: <result>` or why it did not save, and is silent on screen.
- **Logging:** through `AnilBridge.log` when the bridge is loaded, so the setup and the self-check land in the bridge's log; else through `MKXP.puts` when that module exists. Añil's player has no `MKXP` module ([Runtime Reference → Player and Engine](../reference/runtime.md#player-and-engine)), so a copy without the bridge logs nothing.

## Eggs

The eggs are given by `pkmn/games/anil/src/anil/mod/ruby/randomlocke.rb`. What the game was seen to do with them is in [Nuzlocke → Eggs](../reference/nuzlocke.md#eggs).

- **Given at new game:** `Randomlocke.set_up_new_game` calls `give_eggs` right after the randomizer is enabled, before the starter region's save, so the eggs are in the new game's first save. A loaded save never gets more, since the setup runs only when `randomlocke_version` is unset.
- **The box:** the last PC box (box 50 of 50), renamed "Huevos", slots 1–16. A catch sent to the PC goes to the current box (box 1 at first), or else to the first free slot from box 1 on (`S/287_PokemonStorage.rb:232-252`), so it lands beside the eggs only when the current box is box 50 or every box before it is full.
- **The egg:** `Pokemon.new` of a placeholder species, Togepi, at `Settings::EGG_LEVEL` (1), with no moves and the randomizer bypassed (`randomize` false). It gets the name "Huevo", `steps_to_hatch` 100 and the mark `randomlocke_egg` true (an `attr_accessor` the mod adds to `Pokemon`). `pbGenerateEgg` is not used: Challenge Modes wraps it to mark a map when the gift clause is off, Añil's incubator version asks about the incubator, and both add to the party.
- **The species at hatch:** `pbHatch` is wrapped. For an egg carrying the mark, before the game's hatch runs, the mod draws `valid_random_species` at the current badge count (the progressive window, the plugin's blacklist and gens, and the mod's allowed species and forms) and makes a fresh level 1 Pokémon of it with its moves, again with `randomize` false so the species is not drawn twice. It applies `cap_form` and the randomizer's own `ensure_has_damaging_move!`, which `Pokemon#initialize` runs only for randomized creations, so a hatchling gets the same damaging-move guarantee as other new Pokémon. It then copies every instance variable of that Pokémon onto the egg object (the creation stamp included, so `@timeReceived` is the hatch's), removes the mark and logs `randomlocke egg drawn: SPECIES at N badges`. The game's hatch then runs on it as usual: messages, animation, Pokédex, the forced nickname, `hatched_map`. The wrap also covers Añil's incubator, which takes eggs from the party and hatches them through `pbHatch` as the player walks (`S/430_Incubadora.rb:196-206`, `:310-330`). The personal ID, and so the shiny roll, is drawn with the fresh Pokémon. Eggs without the mark (the game's own) hatch unchanged.
- **Logged:** `randomlocke eggs given: 16 in box 50 (Huevos)` at new game.

## Allow-Lists

The allow-lists are built by `pkmn/games/anil/src/anil/mod/allowlists.py`. What the game was seen to do with them is in [Runtime → Randomlocke Mod](../reference/runtime.md#randomlocke-mod).

- **Data:** `pkmn/games/anil/src/anil/mod/data/species.txt` (733), `moves.txt` (558) and `abilities.txt` (164), one Añil symbol per line in PBS order. `types.txt` (733) gives each allowed species-form, in the same order, followed by its official types in PokeAPI's slot order. Species are keyed as `GameData::Species` ids: `BASCULIN` for a base, `BASCULIN_2` for a form.
- **Build script:** `uv run python -m anil.mod.allowlists [PBS folder]`, by default `game/base/es-v4.14/PBS`. It reads PokeAPI's CSV data at a pinned commit (`bc92d3b6029ef1abe9e7ad424c400b338f3c11fe`) and rewrites the four files. PokeAPI names map to Añil symbols by dropping everything but letters and digits, with `NIDORANfE`, `NIDORANmA` and `VISEGRIP` as the only aliases.
  - **Species:** every PokeAPI Gen 1–5 species must resolve in `pokemon.txt`. A base is in when its own `Generation` is 1–5, so `BASCULIN` is left out. A form is in when its base is, it has no `MegaStone` or `MegaMove`, its explicit or inherited `Generation` is 1–5, and it isn't one of the [forms excluded by name](#forced-by-evidence). The build fails unless every species then has as many entries as PokeAPI has Gen 1–5 forms for it.
  - **Moves:** PokeAPI's Gen 1–5 moves found in `moves.txt`, with the absent ones reported ([Runtime → Randomlocke Mod](../reference/runtime.md#randomlocke-mod) names them).
  - **Types:** a base species takes the types of PokeAPI's default form. A form takes the types of the official Gen 1–5 form of its species whose types are the same set as its PBS types, explicit or inherited from the base. Form numbers are not matched, because Añil's do not follow PokeAPI's: Arceus's ??? form is 9 in Añil and 19 in PokeAPI. PokeAPI's `unknown` type maps to `QMARKS`. Any form with no such official form fails the build, so a form Añil retyped could not slip through. The build reports every species whose PBS types differ: 37 of them, of which 33 are retyped and 4 only list their official types in the other order ([Battle Mechanics → Types](../reference/battle-mechanics.md#types)).
  - **Abilities:** the first 164 of `abilities.txt`. The build fails unless the 164th is `TERAVOLT` and the set equals PokeAPI's main-series Gen 3–5 abilities. Añil's own `ABILITY_EXCLUSIONS` are applied with the caps, not removed from the list.
- **Into the game:** `anil.mod.sources` generates `randomlocke_allowlists.rb` (module `RandomlockeAllowLists`, constants `SPECIES`, `MOVES` and `ABILITIES`, plus `TYPES`, a hash from each species-form to its official types) from the data, preloaded after `randomlocke_version.rb` and before `randomlocke.rb`, so every deploy carries it.
- **Failing loudly:** once the plugins load, the mod wraps `Game.set_up_system`, which runs right after `GameData.load_all`. Before it, every name is checked with `exists?` on `GameData::Species`, `Move` and `Ability`, and every type named in `TYPES` is checked on `GameData::Type`. A name that doesn't resolve is logged and raised as a `RuntimeError` whose Spanish message lists the names by list; Essentials shows it in its error box and in `errorlog.txt`, and the game goes no further.

## Applying the Caps

The Gen 1–5 caps and no megas are applied in `randomlocke.rb`. Every patch is made once the plugins load, and each filters what the randomizer picks, except the official types, which are set on the loaded species data, and freeze, which is set on the loaded settings and status data; the PBS and compiled data files are untouched. What the game was seen to do with them is in [Runtime → Randomlocke Mod](../reference/runtime.md#randomlocke-mod).

- **Species:** the randomizer's top-level `random_species` is replaced. Without a mega it samples `RandomlockeAllowLists::SPECIES` and keeps the plugin's `MULTIPLE_FORM_POOL` thinning. For the trainer mega swap it samples the base species of every form with a `MegaStone`, filtered as the plugin does for Pikachu, Eevee, Alcremie and Floette, and kept only when that base is allowed. `valid_pokemon?` also requires an allowed species-form. So every path that draws through `random_species`, including the last pick that `valid_random_species` and the wild table's `find_similar_bst_species` fall back to, gives an allowed species.
- **Species created while random species are paused:** a wild draw leaves random species paused until something resumes them, such as the next species randomized, an in-game trade or a static encounter ([Randomizer](../reference/randomizer.md)), and a paused `Pokemon.new` keeps the species it was given, so an event creating a fixed Gen 6+ gift then would give it unrandomized (Map118 EV26 revives Dracozolt, Arctozolt, Dracovish or Arctovish with `Pokemon.new(pbGet(14), 1)`). `Pokemon#initialize` is wrapped: when randomizing is on and only that pause holds the species back, a species that is not allowed is replaced by a `valid_random_species` draw, marked randomized and logged as `randomlocke paused species capped`. Allowed species, `UNRANDOMIZABLE_POKEMON`, creations with `randomize` false and Pokémon made inside `Randomlocke.keeping_species` are left alone: those received through Cable Club's `parse_pkmn` and the display-only Pokémon of Añil's `MostrarPokemonAnimado#mostrar_poke_animado`, which pauses on purpose to picture a given species. The mod's own draws are named `draw_species` and `draw_move`, because a module method named `random_species` shadows the top-level one when plugin code runs with the module as `self`.
- **Trainer slot forms:** a trainer slot's PBS `Form` is set on whatever species was drawn for it (`S/141_Trainer.rb:139-142`), which gave forms such as `OSHAWOTT_1` and `VULPIX_1`. `process_trainer_pokemon` is wrapped: if the result is not an allowed species-form, it is set to the first allowed form of its species (form and, where the game forced one, `forced_form`), and the change is logged as `randomlocke form capped`. Slots in `UNRANDOMIZABLE_TRAINER_POKEMON` are left alone.
- **Starters:** `generate_random_starters` is replaced by the mod's own draw. The pool is every base species that is allowed, whose whole family (`get_family_species`) is allowed, and that passes the plugin's own starter shape test (two or more family evolutions, exactly one of them from this species), plus the plugin's Monotype type filter. The three are drawn, created at level 5 with random species paused and stored in variables 803–805 as the plugin does. The plugin's non-progressive branches are not kept, since the Randomlocke is always progressive.
- **Evolution:** `Pokemon#check_evolution_internal` is wrapped so that its block is never called for a target species that is not allowed; that evolution then answers nil and the next one is tried. This covers level-up, item and trade evolutions.
- **Moves:** the top-level `random_move` is replaced by a draw from `RandomlockeAllowLists::MOVES`, with the plugin's own OHKO, minimum power and type filters. `find_valid_move` draws only through it, so its fallback after `MAX_ATTEMPTS` is an allowed move too.
- **A typed draw with no move left:** `find_valid_move` is wrapped for the [fallback to every type](#gen-15-caps): when no allowed move of the asked types passes the plugin's own tests for that draw (its `invalid_move?`, so not already in the learnset or blacklisted, and the badge window's power or late-game limit), the draw is made with no type filter, where the same tests still reject a move already in the learnset, and `randomlocke typed moves used up` is logged. The plugin's 30% same-type share is otherwise unchanged.
- **Abilities:** in the `Game.set_up_system` wrapper, after the allow-list check, every ability not in `RandomlockeAllowLists::ABILITIES` is appended to `RandomizedChallenge::ABILITY_EXCLUSIONS`, which both the ability table and the Random Ability Capsule read. Añil's own 25 exclusions stay in the list.
- **Official types:** in the `Game.set_up_system` wrapper, after the allow-list check and before the abilities, each allowed species-form whose `GameData::Species` types differ from `RandomlockeAllowLists::TYPES` gets the official ones as its `@types`. The change is logged as `randomlocke types restored` with the count and the species. This happens on every boot, in memory only. `Pokemon#types` and the battlers read the species data, so new Pokémon, saved Pokémon and battles all see the official types. The order is restored too, so Farfetch'd, Jynx, Smoochum and Altaria are also set, to PokeAPI's slot order.
- **Freeze:** in `Randomlocke.install`, once the plugins have run, `Settings::FREEZE_EFFECTS_CAUSE_FROSTBITE` is removed and set again to false, so every battle method that reads it at call time takes the classic freeze path. `S/117_Status.rb` registered `:FROSTBITE` while the scripts loaded, before the mod could act, so the mod rebuilds `GameData::Status::DATA` with `:FROZEN` in `:FROSTBITE`'s place, keeping its name, animation and icon position. Replacing rather than adding keeps `GameData::Status.count` at six, which the party, summary and battle screens use to find the fainted icon in their status graphics. It is logged as `randomlocke freeze restored` with the status list. A Pokémon saved with `:FROSTBITE` by a game played without the mod is not converted.
- **Mega Evolution:** the new-game setup turns switch `Settings::NO_MEGA_EVOLUTION` (34) on.
- **Forms set later are not capped:** forms the game sets after creation from a held item or the battle (an allowed Arceus holding a Pixie Plate becomes `ARCEUS_18`, Fairy, `S/284_FormHandlers.rb:301`) are outside the randomizer's draws and are left as the game sets them.

## Showdown Export

The pause menu's Showdown export is `pkmn/games/anil/src/anil/mod/showdown.py` and `pkmn/games/anil/src/anil/mod/ruby/showdown.rb`. What the game was seen to do with it is in [Runtime → Randomlocke Mod](../reference/runtime.md#randomlocke-mod).

- **Names data:** `pkmn/games/anil/src/anil/mod/data/showdown.txt`, one `kind SYMBOL Name` line per name (kinds `species`, `items`, `abilities`, `moves`, `natures`), committed like the allow-lists. Its build script is `uv run python -m anil.mod.showdown [PBS folder]`, which reads PokeAPI's English names (`*_names.csv`, language 9) at the allow-lists' pinned commit and maps them to Añil symbols the same way the allow-list build does, with its aliases plus `stick` to `LEEK` and the six stat wings and the Pretty Wing to Añil's `…FEATHER` items. It maps every symbol of `pokemon.txt`, `items.txt`, `abilities.txt` and `moves.txt` that PokeAPI names, and the 25 natures, and reports the rest by name: Añil's own species, items, abilities and moves (2 species, 97 items, 23 abilities and 6 moves at the pinned commit).
- **Showdown spellings:** accents are dropped (Unicode NFKD, combining marks removed), so "Poké Ball" becomes "Poke Ball" as Showdown spells it; Showdown looks names up by their lower-case ASCII letters and digits only (its `toID`), so "Poké" would not match. Nidoran's two species are "Nidoran-F" and "Nidoran-M", since PokeAPI's "Nidoran♀" and "Nidoran♂" reduce to the same letters.
- **Forms:** Añil's form numbers do not follow PokeAPI's (Unown's ? and ! are 26 and 27 in Añil and the other way round in PokeAPI; Arceus's ??? sits at 9; Genesect's drives are Shock, Burn, Chill, Douse), and Añil's Spanish form names are not in PokeAPI for most forms, so each allowed form is mapped by hand to its PokeAPI form, from its `FormName` and types, and the build fails if PokeAPI lacks that form. Arceus's forms are mapped from their PBS type. The name is the species name, a hyphen and the PokeAPI form name with each word capitalised (`ROTOM_2` is "Rotom-Wash", `UNOWN_26` "Unown-Question"). `GIRATINA` is Altered (its `FormName` says "Forma Origen", but its stats and Pressure are Altered's) and `GIRATINA_1` Origin; `BASCULIN` and `BASCULIN_2` are both plain "Basculin", Showdown's Red-Striped (form 0 has Red-Striped's abilities despite its White-Striped name), and `BASCULIN_3` is "Basculin-Blue-Striped". Allowed forms with no Showdown name are reported ([Runtime → Randomlocke Mod](../reference/runtime.md#randomlocke-mod) names them).
- **Into the game:** `anil.mod.sources` generates `randomlocke_showdown_names.rb` (module `RandomlockeShowdownNames`, hashes `SPECIES`, `ITEMS`, `ABILITIES`, `MOVES` and `NATURES` from symbol to name), preloaded after `randomlocke_allowlists.rb`, and `showdown.rb` is preloaded after `randomlocke.rb`, so every deploy carries both. `Randomlocke.after_plugins` keeps a list of blocks, so `showdown.rb` patches the pause menu after the plugins load as `randomlocke.rb` does.
- **The text:** `RandomlockeShowdown.export` writes each party Pokémon that is neither an egg nor permafainted (`perma_faint`, which the Challenge Modes plugin reads as false while its permafaint rule is off) in Showdown's export order: `Nickname (Species)` when `nicknamed?`, else the species; ` (M)` or ` (F)` from the game's gender (none when genderless); ` @ Item` when it holds one; `Ability:`; `Level: 50`; `EVs: 1 HP / 1 Atk / 1 Def / 1 SpA / 1 SpD / 1 Spe`; the nature line; `IVs:` with only the stats below 31, left out when there are none; one `- Move` line per move, Hidden Power without the `[Type]` Showdown's own export adds, since Showdown works the type out from the IVs. Sets are separated by a blank line. The species-form is `GameData::Species.get_species_form(species, form)`, so a form with no data of its own exports as its base. The nature is the one the stats use (`nature_for_stats`, a mint's when there is one), and a Hyper Trained stat (`ivMaxed`) counts as 31. Gender is included because the game fixes it and Showdown would otherwise choose; shininess and happiness are left out, being outside what was asked. The first name with no mapping raises `RandomlockeShowdown::MissingName` (`especie ARCEUS_9`, for example).
- **The key:** `DP_PauseMenu#draw_helpful_text` is wrapped to grow the info box up by one 30-pixel line and 1.45 times wide (from 1.3), so the label fits, and to draw "[Z] Exportar a Showdown" above "Nivel máx. actual". `DP_PauseMenu#update`, called once per frame of the menu's loop, is wrapped: on `Input.trigger?(Input::ACTION)` it plays the decision sound and runs `RandomlockeShowdown.copy`. That sets `Input.clipboard` to the text and says, in Spanish, that the team was copied and to paste it into Showdown's teambuilder with Import. An empty export (no Pokémon but eggs and dead ones) says so and copies nothing; a missing name says which and copies nothing. The game's scripts are not edited, and the menu stays open afterwards.

## How the Checks Run

`anil check` is `pkmn/games/anil/src/anil/harness/check.py`, copied from Wonder's with the renames of [Runtime Design → Decisions](runtime-design.md#decisions). What the checks saw on the game is in [Runtime → Checks](../reference/runtime.md#checks).

- **Command:** `anil check NAME...` takes check names and groups. `newgame` is `overworld`, `challenge`, `randomizer`, `completo`, `set-style`, `wild-hidden`, `rulebook`, `intro`, `mark`, `updater`, `discord`, `no-mega`, `starter-region`, `new-game-save`, `eggs` and `egg-hatch` (the last two in [Eggs](#eggs)). `nuzlocke` is `challenge-start`, `mart-bans`, `permafaint`, `clauses`, `first-encounter`, `catch-nickname`, `hall-of-fame`, `party-wipe`, `total-wipe` and `level-cap`. `random` is `random-species`, `random-starters`, `random-learnsets`, `random-abilities`, `random-trainers`, `random-tms`, `random-marts`, `random-items`, `random-wild` and `random-reload`. `caps` is `evolutions` and `megas`. `battle` is `battle-mechanics`, `official-types`, `freeze`, `calc` and `calc-moves`. `shiny` is `shinies`. `stats` is `ivs-evs`. `showdown` is `showdown`. `stage0` is `launch`, `handshake`, `eval`, `saves`, `snapshot` and `replay`. `all` is `newgame`, `nuzlocke`, `caps`, `battle`, `shiny`, `stats`, `showdown`, `random` and `stage0`, in that order. Each check prints `pass` or `FAIL` and its evidence, one line per expectation. The command ends with a count and exits 1 if any check failed.
- **Against the live game:** the checks attach to the running session as the driver `anil check`. They don't launch a game or play the intro themselves. "From a fresh new game" means a session started with `anil run` on an empty save and driven through the intro. `launch` checks that session's lock, its game process, its `launch.json`, the deployed bridge and the handshake line in `harness.log`.
- **The expected configuration is stated twice:** `anil.harness.check` holds its own copy of the configuration in this doc. It does not read the mod's constants, so a wrong constant in `randomlocke.rb` fails a check.
- **Reads, not evals, for state:** game state comes from one `read` per new-game check, which is not recorded and leaves the digest alone. Evals are used only where game code must run: the Options entries, the locked setters (the original values are put back afterwards), the updater methods and `Game.save`. `eggs` reads the egg box in three reads (the box count, the box's size, then its slots) and reads the save back by eval as `new-game-save` does; `egg-hatch` changes the game, so it runs inside a snapshot it restores, and sets its situation up by eval. The updater methods are called only after `source_location` places all three in `randomlocke.rb`, so a failed hook never reaches the real updater.
- **Mode menus never shown:** `overworld` tests Map104 and Map217 against `$PokemonGlobal.visitedMaps`, plus the idle overworld context on Map028.

It then saves a snapshot `check-shiny-<session>-<tick>`, moves to map 3 and makes Pokémon in evals of 2,000: 100,000 wild Pokémon from the land table through `choose_wild_pokemon` and `pbGenerateWildPokemon` with the chain cleared; 20,000 with `@salvajes_visibles_en_ow` set to 0 past the mod's locked setter; 20,000 Rattata with a chain of 40 Rattata and random species paused (`dont_randomize` holding Rattata so `pbGenerateWildPokemon` does not resume it); 20,000 with a Shiny Charm in the bag; and 40,000 `Pokemon.new`. Each is counted shiny by its personal ID, recomputed in the eval, and by `shiny?`. A count passes when it lies within four standard deviations of the binomial mean the code's odds give, so a pass says the code's odds hold, not that the sample hit them exactly. It then turns on the Shiny Potion's switch and makes one wild Pokémon, calls the chain's `on_wild_battle_end` handler directly for a fixed sequence of outcomes with its messages off, loads every 25th trainer through the randomizer, and restores the snapshot. The using of the potion, the chain in real battles and the number-battled bonus are not driven.
- **IVs and EVs through the item handlers:** `ivs-evs` reads the IV and EV settings and limits, switch 149 ("Sin Grindeo"), whether the Charms Case plugin is installed, and each IV or EV item's name, price, flags and randomizer status by eval. It scans every map event's script blocks for marts selling those items, for `PunchBag` calls and for `ivMaxed`. The items are used through `ItemHandlers.triggerUseOnPokemon` on `Pokemon.new` Rattata with random species paused, with a stand-in scene that records the messages instead of the party screen; the power items and the Macho Brace go through `Battle::ItemEffects.triggerEVGainModifier` on a Rattata's yield, not through a battle. IVs are sampled from 3,000 `pbGenerateWildPokemon` and 3,000 `Pokemon.new`, and pass when every value's count lies within four standard deviations of uniform. Every 25th trainer is loaded through `pbLoadTrainer` and its IVs and EVs compared with the PBS. Last, under a snapshot `check-stats-<session>-<tick>`, the party becomes the first starter, `pbDrawTextPositions` is wrapped to record what is drawn (put back afterwards), the summary is opened in an interpreter script and Right is pressed until `page_allstats`, and the drawn EV/IV pairs are compared with the Pokémon's. Buying from the marts and the punch-bag minigame are not driven.
- **The Showdown export on a known party:** `showdown` saves a snapshot `check-showdown-<session>-<tick>` and restores it at the end, so it runs in any order. It replaces the party with a known one made by eval with randomizing off: a nicknamed Rotom-Wash with Leftovers and two IVs below 31, a Nidoran-F with no item and every IV 31, an egg, a nicknamed male Farfetch'd with a Leek, a female Basculin-Blue-Striped with a King's Rock, and an Unown-Question with a Poké Ball, a Hyper Trained Attack and a Bold mint; forms are set with `form_simple=`, since `form=` runs form-change code that can show messages inside the eval. It compares `anil.harness.showdown.export_party` with its own copy of the expected text. Then, if the challenge has not begun, it runs `ChallengeModes.begin_challenge` and requires the PERMAFAINT rule on; it sets the Nidoran-F's HP to 0, requires it to be permafainted, and requires the export to be the same text without the Nidoran-F; from here on the expected text is that one. Then it sets the clipboard to a marker and reads it back from Windows, opens the pause menu with B (pressing again if the menu has not opened within 60 ticks), takes a screenshot, presses Z (`ACTION`) and waits for the message, and requires the game's `Input.clipboard` (line ends normalised) and the Windows clipboard (`Get-Clipboard -Raw` through `powershell.exe`, UTF-8) to hold the expected text. It presses C until the message closes and B to close the menu. Last, it makes the party one Arceus of form 9 and requires the export to fail naming `especie ARCEUS_9`. After the restore it sets `ChallengeModes@@started` back to the value it read first, since a restore re-runs the challenge's load hook only for a challenge already running. Pasting into Showdown's teambuilder is not driven: Showdown is a website outside the game.
- **Evidence in the session:** each check writes a `check` entry (`name`, `passed`, `evidence`) through `note`. The `replay` entry goes to the replayed session, since the original game has stopped by then. Replay skips `check` entries.

## Decisions

### Scope

- **Out:** the English build and other Añil versions. _(settled 2026-10-02)_
- **The level cap is a hard cap:** Añil's Level Caps EX plugin is checked in game, and if its cap did not hold against Rare Candies or battle EXP, the mod would turn on its hard cap (candies refused and EXP stopped at the gym's cap). Why: players must not pass the cap. Checked in game 2026-10-02: the cap holds as shipped and nothing in the game lifts it, so the mod sets and holds nothing ([Level Caps](../reference/level-caps.md)). The competition's own level caps stay with the group's rules. _(owner, settled 2026-10-02; replaces "left as shipped")_
- **Monotype, VGC (switch 147), Inverso (148) and Sin Grindeo (149) stay off,** because the mode menu that sets them is blocked ([Package Behaviour](#package-behaviour)). _(settled 2026-10-02)_
- **What losing the challenge means for the competition is a group rule,** not game behaviour ([Series 1 Rules → Losing the Challenge](../../../series/1/reference/rules.md#losing-the-challenge)). _(settled 2026-10-02)_
- **The mod enforces only what the game can see:** of the group's rules, it gives the eggs (at new game, quick to hatch, never using a route) and leaves dead Pokémon out of the export; every other group rule is honoured by the players, since the game cannot tell who won a match. Why: the owner's choice ("we honour the player"). _(owner, settled 2026-10-02)_
- **The mod reuses Añil's own plugin APIs** (`ChallengeModes`, `RandomizerConfigurator`, `RandomizedChallenge`) rather than reimplementing rules. _(settled 2026-10-02)_

### Configuration Source

- **The owner's configuration** came as `reglas_anil_para_amigo(1).zip` (sha256 `a7a1e4b03ed9737342568d764ea129de5b64e4257de36cc95ce7626d7489bb6f`, in `C:\Users\david\Downloads\`), a fixed version of an earlier `reglas_anil_para_amigo.zip`. It holds a preload `reglas_anil.rb` that overwrites a save's options once the player has chosen Nuzlocke and Random at the PC. The package applies the same options at new game, with no menus: its Nuzlocke and randomizer values are the configuration below, and its trigger and mechanics are not reused. _(settled 2026-10-02)_
- **The script's `$PokemonSystem` gameplay options are ignored:** `battlescene`, `show_pokemon_on_change`, `sendtoboxes`, `givenicknames`, `runstyle`, `guardar_al_curar`, `show_damage_numbers`, `mensaje_shinys`, `ask_text`, `moves_option`, `surf_option`, `expshareon`, `only_speedup_battles` and `battle_speed` keep Añil's defaults and stay player-adjustable. Only battle style and visible wild Pokémon are set and locked ([Package Behaviour](#package-behaviour)). Why: the owner's choice; the one option players must not change is fixed battle style. _(owner, settled 2026-10-02)_
- **Game methods are wrapped by alias chaining, never `prepend`,** in the mod and the bridge. Why: the configuration's first version prepended a module to `Graphics.update`; plugins such as Discord RPC alias `Graphics.update` later, and an alias of a prepended method recurses forever, so the fixed script chains with `alias`. _(settled 2026-10-02)_

How each rule behaves in game is in [Nuzlocke](../reference/nuzlocke.md). _(owner, settled 2026-10-02)_

- **The challenge does not end after the league:** Añil's own behaviour is kept ([Nuzlocke](../reference/nuzlocke.md)), and the mod changes nothing. Why: the owner's choice. _(owner, settled 2026-10-02)_

### Randomizer

- **"Random Completo" (never Semi Random), with these options:** on, `PROGRESSIVE_RANDOM`, `RANDOMIZE_POKEMON`, `CONSISTENT_ENCOUNTERS`, `RANDOMIZE_MOVES`, `PRIORIZE_STAB_IN_LEARNSET`, `DIFFERENT_MOVESETS_PER_FORM`, `BAN_OHKO`, `RANDOMIZE_TM_COMPATIBILITY`, `RANDOMIZE_TRAINERS`, `REMEMBER_TRAINER_TEAMS`, `RANDOMIZE_TRAINER_ITEMS`, `RANDOMIZE_ITEMS`, `RANDOMIZE_HELD_ITEMS` and random starters; `RANDOMIZE_ABILITIES` = `:FULLRANDOM`; `GENS` = 1–5; off, `RANDOMIZE_TYPES` and the three random-evolution options. - **Enabled by setting its parts, not by `RandomizedChallenge.enable`:** the setup sets `$PokemonGlobal.random_gens` and the options, the ability mode through `RandomizerConfigurator.ability_mode=` (which sets switch 48 and regenerates abilities), and `random_enabled`, and generates the random starters, all after the player exists and before the starter list is shown. ### Package Behaviour

- **A new game skips three menus:** difficulty (Map104 "Modo Juego") is answered Completo (switch 110); visible overworld wild Pokémon (Map217) is forced off and hidden from Options; the PC's "Elegir modo de juego" (Map028 ev24) is blocked. Completo was chosen as the mode that keeps normal encounter tables and leaves the bag block off, where Clásico would also force gens 1–2 and three starters; what each mode does in game was not checked. With the option forced off, nobody picks encounters by sight. _(owner, settled 2026-10-02)_
- **The `:RULEBOOK` item replaces the blocked PC menu:** the player receives it, the item the PC normally gives after choosing modes, which shows the active rules. Why: the owner's choice. _(owner, settled 2026-10-02)_
- **Battle style is Set** ("Fijo", `$PokemonSystem.battlestyle = 1`) from new game, and locked: hidden from Options, and players can't switch to Cambio. `FORCE_SET_BATTLES` alone would only set it when the challenge starts. Why: the owner's choice; it is the one option players must not change. _(owner, settled 2026-10-02)_
- **No external calls: the updater's startup version check and Discord Rich Presence are off; Multi Save stays,** in every copy of the game, with or without the bridge. Cable Club's own sockets are untouched and unused. Why: the owner's choice. Verified rules can't drift mid-competition through a self-update replacing v4.14, and the package makes no network calls. _(owner, settled 2026-10-02)_
- **Players' saves go to Añil's own save folder,** shared with any normal Añil install; the package does not redirect them. Only games the harness runs are redirected, by the bridge ([Runtime Design → Saves](runtime-design.md#saves)). Why: the owner's choice. _(owner, settled 2026-10-02)_
- **No starter-region question:** Añil's starter-region menu (`pbMostrarListaStarters`, `P/Misc Scripts Añil/008_Menú de starters.rb`, run by Map028 EV18 when the player first wakes in the bedroom) is replaced by a silent default that records a choice the way the menu does: switch `334 + index` and variable 31 (`PBEleccionStarters::CHOSEN_STARTERS`), which later events read. Why: the owner's choice; with the randomizer on and the Kanto default recorded, the lab's Poké Balls give the three random starters ([Runtime → Randomlocke Mod](../reference/runtime.md#randomlocke-mod)), so the question only costs the player a screen. Not every region would do: index 1 would remove a Poké Ball ([Forced by Evidence](#forced-by-evidence)). _(owner, settled 2026-10-02)_
- **A new game saves itself once,** when it reaches the bedroom, into a new slot taken from Multi Save's own `SaveData.get_new_manual_slot` (`P/Multi Save/Multi Save.rb:99`), never over an existing save. Why: the owner's choice. The three random starters are drawn at new game, so with them in a save from the start a player can only reroll them by replaying the intro in another new game; the save folder is shared with normal Añil, so the save must never overwrite one already there. _(owner, settled 2026-10-02)_
- **The party can be copied to Pokémon Showdown** from the pause menu, which copies the party, eggs and dead Pokémon left out, to the clipboard in Showdown's team format. Every Pokémon is exported at Level 50 with its nickname, its real in-game IVs (only the stats below 31 listed, as Showdown expects) and an explicit EV line of 1 in every stat, so the result never depends on how Showdown fills a missing EV line. Species and forms, items, abilities, moves and natures carry Showdown's English names, mapped from the game's IDs through PokeAPI at the allow-lists' pinned commit, and an ID with no mapping makes the export refuse rather than guess (the allowed form with none is in [Runtime → Randomlocke Mod](../reference/runtime.md#randomlocke-mod)). It is in every copy of the game. The pause menu cannot take an eighth row, so the option is a key, not a row ([Forced by Evidence](#forced-by-evidence)). Why: the owner's choice, so players can bring their current party into Showdown; the export leaving out dead Pokémon itself prevents mistakes in a pokepaste. _(owner, settled 2026-10-02; dead Pokémon left out 2026-10-02)_
- **The install shows it is right:** the window title carries "Randomlocke vN", and at boot the mod checks it runs on the official v4.14 (a CRC of `Scripts.rxdata` and `PluginScripts.rxdata`, using in-engine Zlib). If not, it says so in Spanish. _(settled 2026-10-02)_

### Gen 1–5 Caps

The rules as players read them are in [Series 1 Rules → Gen 1–5 Limits](../../../series/1/reference/rules.md#gen-15-limits).

- **Species: strictly Gen 1–5,** as an explicit species-and-form allow-list. It covers wild, trainer, gift, static, trade and starter Pokémon, the trainer mega swap (`P/Random…/006_Trainers.rb:93`) and every fallback path, so nothing escapes through an unvalidated last pick. Excluded: later-gen evolutions that Añil's baby-generation test lets in (`001_Main.rb:351`: Sylveon, Kleavor, Annihilape, Kingambit, Obstagoon, Perrserker, Añil's ROYALEON and CEFIREON, …), and every non-official-Gen-1–5 form: regional, Primal, mega and fan forms. Starters: families with any Gen 6+ member are also excluded. _(owner, settled 2026-10-02)_
- **Evolving into a Gen 6+ species is blocked,** via `Pokemon#check_evolution_internal` (`P/Random…/005_Evolutions.rb:116`, used by every evolution check). _(owner, settled 2026-10-02)_
- **Moves: an allow-list of official Gen 1–5 moves,** built from Añil's PBS data cross-checked against PokeAPI (558 moves, `VISEGRIP` included), committed as data, and failing loudly if a name doesn't resolve. `VISEGRIP` is in; `EEVEEVOLLEY`, `NIHILLIGHT` and Añil's custom `TRIPLEHIT`, `ESCALOFRIO`, `DESLIZAMIENTO` and `ATRAPAMOSCAS` are out, and so is the official move Añil's `moves.txt` lacks ([Runtime → Randomlocke Mod](../reference/runtime.md#randomlocke-mod)). It is applied by overriding the randomizer's `random_move` (`P/Random…/004_Moves.rb:191`), which every randomized-move path uses, so the allowed set always yields a valid pick and the badge power limit can't be broken by the fallback. Why: the owner chose to exclude all customs. _(owner, settled 2026-10-02)_
- **A typed move draw with no move left falls back to every type:** the allow-list leaves some types few moves (Fairy has only Charm, Moonlight and Sweet Kiss), so a same-type learnset or moveset draw could run out and `find_valid_move` returned a repeated or over-powered last pick after `MAX_ATTEMPTS` (a Togepi learnset repeating a move; a Dratini at 0 badges given Draco Meteor, where the Dragon moves left were over the early power limit rather than used up). When the type-matched allowed moves are used up, the draw falls back to another allowed Gen 1–5 move of any type not already in that learnset, rather than allowing repeats or reshaping the allow-list ([Applying the Caps](#applying-the-caps)). Why: the owner chose the least intrusive fix. _(owner, 2026-10-02)_
- **Abilities: the first 164 entries of `abilities.txt`** (Gen 3–5, ending at `TERAVOLT`), minus Añil's own exclusions. Custom abilities are out. It is applied through `ABILITY_EXCLUSIONS` before the ability data is generated, and also feeds the Random Ability Capsule. _(owner, settled 2026-10-02)_
- **Legendaries stay in the pool,** as the randomizer does by default. Whether they may be used is a group rule: never ([Series 1 Rules → Rules in Every Battle](../../../series/1/reference/rules.md#rules-in-every-battle)). Why: the owner's choice. _(owner, settled 2026-10-02)_
- **No Mega Evolution:** switch 34 ("No Mega Evolución", `Settings::NO_MEGA_EVOLUTION`) is on from new game. Base Essentials and DBK check it in `pbCanMegaEvolve?`. Mega Stones remain as useless items, and trainers keep holding them. _(owner, settled 2026-10-02)_
- **Static data is never edited or deleted:** PBS and compiled data stay, because editing them would break learnsets, trainers, TM items, mega forms and saves. Every cap filters what the randomizer picks; the one change to species data, the official types, is made in memory at boot. _(settled 2026-10-02)_
- **Every allowed species has its official types,** the current ones from PokeAPI at the allow-lists' pinned commit. Añil's own retypings, such as the Chikorita line as Grass/Fairy and Feraligatr as Water/Dragon, are undone; official Gen 6 retypings stay, such as Clefairy and Togepi as Fairy. The mod sets the types at boot and leaves PBS and compiled data untouched ([Applying the Caps](#applying-the-caps)). Why: the owner's choice. _(owner, settled 2026-10-02)_
- **Freeze, not frostbite,** as in the official Gen 9 games ([Battle Mechanics → Statuses](../reference/battle-mechanics.md#statuses)). Añil's frostbite is turned off by the mod at boot, and the game's scripts are not edited ([Applying the Caps](#applying-the-caps)). Why: the owner's choice. _(owner, settled 2026-10-02)_

### Checks

- **The tests are `anil check <rule>` commands** that run against a live game through the bridge (eval, snapshots, driven input) and print pass or fail with evidence; `anil check all` runs the full set from a fresh new game. They are runnable procedures, not automated tests or CI ([CLAUDE.md](../../../../../CLAUDE.md)). Reading code never counts as proof. Every rule is to have a check that passes against the real game ([How the Checks Run](#how-the-checks-run)). _(owner, settled 2026-10-02)_
- **Each check records its evidence in the session** ([How the Checks Run](#how-the-checks-run)). _(settled 2026-10-02)_
- **A form the game sets at creation is judged by the form the randomizer drew.** The randomizer checks the base stat total of the species it draws, and `Pokemon.new` then sets a form-at-creation species' form from where it is made, so base Wormadam (470, inside the 460–800 window of 7+ badges) can become Trash Cloak Wormadam (424) ([Randomizer → Species](../reference/randomizer.md#species)). The `random` checks accept a non-base form outside the window when its base form is inside it, and the mod stays as the players have it. _(owner, 2026-10-22)_

### Forced by Evidence

One workable option left by a game fact, recorded rather than asked ([Write Documentation → Recording Decisions](../../../../general/how-to/write-documentation.md#recording-decisions)).

- **The Windows clipboard is read up to five times, 0.2 s apart, until it is not empty.** Another program holding the clipboard makes `Get-Clipboard` answer empty: `showdown` failed once in `all` on an empty read right after the game set the clipboard, and passed alone twice and in every later run. _(forced by evidence, 2026-10-22)_
- **Basculin: only the Gen 5 forms are in.** In Añil, form 0 is the Gen 8 White-Striped form (`[BASCULIN]`, "Forma Raya Blanca", `Generation = 8`). Red-Striped and Blue-Striped are forms 2 and 3 (`pokemon_forms.txt`, `Generation = 5`), and there is no form 1. So `BASCULIN` (form 0) is excluded, and `BASCULIN_2` and `BASCULIN_3` are allowed. Form numbers follow Añil's PBS, not the official games, so the allow-list is keyed by Añil's species-form symbols. _(2026-10-02)_
- **Fan forms marked Gen ≤ 5 are excluded,** such as `[KINGLER,1]` "Mega Kingler" marked Gen 1, because form generation is inherited from the base species (`S/401_Compiler_CompilePBS.rb:456`). The build leaves mega forms out by their `MegaStone` or `MegaMove` key ([Allow-Lists](#allow-lists)). _(2026-10-02)_
- **The randomizer's per-slot TM-compatibility file is reset at new game.** `tm_compatibility_<slot>.dat` in the save folder overwrites in-memory data on load (`001_Main.rb:221-253,825`), so a file left by an earlier game in that slot would leak into a new one. _(2026-10-02)_
- **The slot's TM-compatibility file is also rewritten when the game is saved.** A new game has no slot until its first manual save (`$player.save_slot` is nil, so the file is `tm_compatibility.dat`), and Multi Save only sets the slot inside `Game.save` (`P/Multi Save/Multi Save.rb:801`). So the stale file of an earlier game in that slot can only be overwritten at or after that save, and a reset at new game alone cannot reach it. Since the new-game save ([New-Game Setup](#new-game-setup)), that first save is the automatic one in the bedroom. _(2026-10-02)_
- **Skipping Map104 and Map217 means doing their side effects.** Map217 EV1 also gives the running shoes, sets variables 76, 78 and 79 to 31, 4 and 8, re-enables the menu, makes the player visible again (Map001 EV2 set its opacity to 0) and sets the screen tone back to normal (the intro turned it black with `pbToneChangeAll`); Map104 sets switch 110 for Completo; everything else it does (its cursor variable 104, switch 323, its self-switch A and disabling the menu, which Map217 re-enables) only matters to Map104's own events or is undone on the way. _(2026-10-02)_
- **Forms whose inherited generation is wrong are excluded by name.** Pikachu forms 2–16 (cosplay, caps and the fan "Forma Amarillo"), `EEVEE_1` ("Eevee Lets Go"), `DIALGA_1` and `PALKIA_1` (Origin Forms) and `KYUREM_3` and `KYUREM_4` (no form name, `PokedexForm` 1 and 2) carry no `Generation`, so they inherit Gen ≤ 5 from the base, but none is a Gen 1–5 form in PokeAPI. With them out, every official species has exactly as many allowed entries as PokeAPI has Gen 1–5 forms for it, gender-only forms aside (Essentials has none for Frillish and Jellicent). _(2026-10-02)_
- **The starter-region default can't be "Let's Go".** Index 1 sets switch 335, and Map029 EV29's page 3 on switch 335 is empty and comes after its switch-350 random page, so it would remove the middle Poké Ball even with the randomizer on; EV12's page 2 on switch 335 is empty too, and EV28's non-random page, the rival (EV2), Oak (EV13) and Map091 EV42 branch on it (every page condition and switch branch of Map029 and Map091 read). _(2026-10-02)_
- **The Showdown export is a key in the pause menu, not an eighth row.** Añil's pause menu (`P/PauseMenuDP/Script.rb`) draws its rows 48 pixels apart in a viewport 24 + 48 × rows high, from y = 4, with the 48 fixed in its input loop's selector and mouse code too. Seven rows (Pokédex, Pokémon, Bolsa, the trainer card, Guardar, Opciones, Salir) end at y = 364 on the 384-pixel screen (`Settings::SCREEN_HEIGHT`), so an eighth would end at 412, off screen. The menu's own extras are keys drawn beside it ("[S] Volar", "[A] Vial", "[D] Radar", "[W] Rep. Inf."), and of the named buttons (`S/012_Input.rb`, with their keys in `mkxp.json`'s `bindingNames`) its loop reads all but Z (`Input::ACTION`) and Q (`Input::AUX1`), which `S/425_Turbo.rb` already takes for the speed-up toggle. So the export is Z, labelled "[Z] Exportar a Showdown" in the menu's bottom-left info box. A fifth key panel on the left would overlap that box once all four of the others show, since `consistent_wild_encounters` lets the Radar show in the Randomlocke. _(2026-10-02)_
- **Set style has to be locked at the setter, not only in Options.** Map028 EV21 "Combate fijo", an action-button event with no condition, sets `battlestyle` to 0 unless switch 666 (Modo Radical) is on. _(2026-10-02)_
