# Rules Engine Design

How the harness judges actions against the group's rules, the ones the game and the verbs leave unenforced: deterministic, with no judgment in it. The rules themselves are owned by series 1's rulebook ([Rules → The Group's Rules](../../../series/1/reference/rules.md#the-groups-rules)); this doc owns how the engine enforces them, as built. The code is `anil.harness.rules`, with the ledger read by `anil.harness.state`, the bridge's `anil_rules.rb` and the `anil rules` commands in `anil.cli`. It is copied from Wonder's rules engine design (Wonder: `docs/subsystems/harness/explanation/rules-engine-design.md`), where it was scoped with the owner on 2026-10-04, built and checked against the game, without Wonder's run records, its Wonder fight rounds and egg guard, its frozen paste files, its agent and its control panel. Sessions named as evidence ran under Wonder's harness unless said otherwise, whose commands, files and bridge module read `wonder` where `anil`'s read `anil` ([Runtime Reference](../reference/runtime.md)).

It builds on the verbs it stands in front of, which stay unenforcing ([Menu Design → Scope and Interfaces](menu-design.md#scope-and-interfaces), [Battle Layer Design → Scope and Interfaces](battle-layer-design.md#scope-and-interfaces), [Dialog Design](dialog-design.md), [Navigation Design](navigation-design.md)), and on the game database for item, move, species and gift facts ([Game Database Design](game-database-design.md)). Game facts cited here are owned by State → Rules Ledger (Wonder: `docs/domains/game/reference/state.md` → Rules Ledger) (the save's ledger, as verified), [Runtime → Payload Wrappers](../reference/runtime.md#payload-wrappers) (the catch's `store` payload) and World → Item and Gift Events (Wonder: `docs/domains/game/reference/world.md` → Item and Gift Events) (the marts the competitive items are drawn from). The engine needs only Python in WSL and the existing bridge: no Windows-side pieces, no secrets or config, and no models.

## What the Engine Does

Guard and audit:

- **`check(action, facts)`** takes a typed action mirroring a verb's arguments (`Buy`, `Sell`, `UseItem`, `GiveItem`, `TakeItem`, `Swap`, `SetExpShare`, `Vial`, `Save`, `Pc`, `Interact`, `Walk`, `Fly`, `ContinueDialog`, `ContinueMenu`, `ContinueBattle`, `Run`, `Switch`, `BattleItem`, `Fight`, `Store`, `Choose`, `Relearn`) and returns a `Verdict`: allowed, or refused naming the rule, with a reason that tells no more than the player knows. `anil rules check` calls it; the verbs never do.
- **`audit(facts)`** returns the standing obligations, each an `Obligation` with a duty ("take the item", "deposit at the next PC", "move it off the lead", "release at the next PC", "withdraw at the next PC", "freeze the paste"), the rule, a reason and what it blocks. A blocking obligation makes `check` refuse the actions it names until it is cleared; one that blocks nothing is a reminder.
- **`summary(facts)`** is the audit with the counts beside it (`Audit`): the obligations, the shinies counted and those past the 6th, the competitive items bought, the badges, the pastes frozen and the gym due.

Both are pure functions of `Facts`: one `anil.harness.state` read with its rules ledger, the legendary species, balls, healing items, sleep and OHKO moves and gift events from the game database, and whether the running wild battle can be fled. `guard` and `run_audit` read the live game once, call them and record what they found. `run_freeze` is the one call that writes game state: it records the due gym as frozen in the save's ledger.

## Scope Edges

Every rule of series 1 that binds a player's own actions in the game is in: the field actions, the party rules, the battle clauses and the pastes. Out: strategy (which Pokémon to freeze, when to fly, whether to catch; the engine only says what is allowed), routing, the league's matches on Showdown, and the eggs, since opening one is the player's word that they won a league match and nothing in the game counts wins ([Rules → Eggs](../../../series/1/reference/rules.md#eggs)). Fair play (no reloading, no bugs or glitches) is honour: `anil` keeps no run records, so nothing tells a reload from a fresh launch ([Runtime Design → Left Out](runtime-design.md#left-out)). Pokérus is not a rule at all ([Decisions → Field Actions](#field-actions)).

### The Freeze Route

A pending freeze refuses the battles a player could avoid, and the route that avoids them is flying with the PokéRider to the gym's city, which lands at the Pokémon Center's door (owner). Flying is harness work beside the engine, not the engine's: the menu layer's `fly` verb, through the pause menu's "[S] Volar" shortcut and the region map ([Menu Design → Flying](menu-design.md#flying)), and navigation's flight exit, which `anil go` takes whenever flying is cheaper ([Navigation Design → Flying](navigation-design.md#flying)). Where the PokéRider is got, where it flies from and where it lands are in World → Flying (Wonder: `docs/domains/game/reference/world.md` → Flying). No rule binds a flight itself; the engine's `Fly` action is refused only by the obligations that block walking, since a landing runs the map's autoruns and can start a battle ([Decisions → Field Actions](#field-actions)).

## The Ledger

What happens in game is counted in the save, where it can never disagree with the game and also records what happens while the owner plays by hand: `$PokemonGlobal@anil_rules`, written by the bridge, holds every item bought on a buy screen, every shiny owned by personal ID, which of our moves put each foe to sleep, and the gyms whose paste `anil rules freeze` froze. The ledger's layout but `frozen` is in State → Rules Ledger (Wonder: `docs/domains/game/reference/state.md` → Rules Ledger); `frozen` is a list of gym numbers. The freeze state is derived from the badges and `frozen`, never stored.

## Commands

`anil rules check <verb> ARGS` judges one action against the live game, `anil rules audit` prints the obligations and the counts, and `anil rules freeze` freezes the due gym's paste ([Decisions → Build Choices](#build-choices)). All three take `--build` on `rules` and open the game database.

## Observability

Each `guard` and `run_audit` writes a `rules` record entry through `note` (`stage` `check` or `audit`), `run_freeze` one with `stage` `freeze`, and an allowed `fight` while a freeze is pending one with `stage` `forced`. The bridge writes `rules_bought` and `rules_shiny` entries itself, and `rules_sleep` too; replay skips all four kinds ([Runtime Design → Session Records and Replay](runtime-design.md#session-records-and-replay)). Guards, audits and freezes log to the `anil.harness.rules` logger, and the ledger's changes to the bridge log.

## Re-running and Rollback

`check`, `audit` and `summary` are pure functions of state and ledger, so they are safe to rerun. The ledger rewinds with the save and with a snapshot restore, the frozen gyms included, so a restore from before a freeze makes it due again. Reverting means removing the hooks and the module; a save that carries the variable still loads, since Marshal keeps any instance variable.

## Decisions

The owner's answers from Wonder's scope, 2026-10-04, as they stand for series 1.

### Scope and Interfaces

- **Guard and audit:** `check(action)` before a verb runs, allowed or refused naming the rule; `audit(state)` the standing obligations, each blocking the actions it names until cleared or not. The verbs stay unenforcing. Why: refusing before the act is the only way to keep an irreversible breach (a vitamin used, a seventh shiny caught) from happening; audit alone learns of it too late, and enforcing verbs contradicts the settled "verbs do what they are told" decisions. _(from Wonder, owner, 2026-10-04)_
- **No `anil` verb calls the guard:** `anil rules check` asks it about one action, and the owner, or Claude driving the game, runs it before the verb. Why: Wonder's guard was called by its agent's tool API, which does not come over; the menu and battle verbs stay unenforcing, as their decisions settle. _(2026-10-21, forced by the scope)_
- **The interfaces:** typed actions mirroring the verbs' arguments, a verdict whose reason tells no more than the player knows, obligations naming the actions they block; nothing external, Showdown and pokepast.es included. _(from Wonder, owner, 2026-10-04)_
- **No egg guard, no run records, no paste files:** Wonder's guard counted eggs from Wonder fight rounds in its run records, and neither comes over; the paste files lived in the run folder. Every other rule of Wonder's guard and audit stays. _(settled 2026-10-21)_

### Field Actions

- **The competitive items are every shop item with an in-battle held effect:** the type Gems, Focus Sash, the lenses, the herbs, King's Rock, BrightPowder, Eject Button, Red Card, the incenses and the held battle berries (type-resist, pinch, Custap, Jaboca, Rowap, Kee, Maranga, Enigma and the like). The limit is one in all per item ID, across every shop, Battle Point shops included. The guard refuses a `buy` that would take the count past one. _(from Wonder, owner, 2026-10-04)_
- **Healing items on the visit that starts the challenge:** while the challenge is queued (`challenge_qued`, read with the state), a `buy` holding a Poké Ball (the item flag `PokeBall`) and a healing item (the flag `Healing`) is refused, whichever comes first in the call. Why: the game picks its bans when the buy list opens, so on that visit it would sell them. _(from Wonder, owner, 2026-10-06)_
- **Mints are allowed freely:** they change the nature, not EVs or IVs. _(from Wonder, owner, 2026-10-04)_
- **EV and IV items:** `use_item` is refused for vitamins (HP Up included), Mochis (Fresh Start included), feathers, EV-reducing berries and Chapas; `give_item` for the power items and the Macho Brace. Buying them is not a breach, so `buy` lets them through. The punch-bag trainers in the Dojo Azafrán are refused at `interact`. _(from Wonder, owner, 2026-10-04)_
- **A Pokémon that arrives holding a power item or the Macho Brace** raises a blocking "take the item": until `take_item` clears it, anything that can start a battle is refused (walking and `interact`). _(from Wonder, owner, 2026-10-04)_
- **What a blocking obligation leaves allowed:** `save`, `sell` and `set_exp_share` start no battle, so a blocking obligation never refuses them; `fly` blocks as walking does, and `continue_dialog` and `continue_menu` are never refused by one, since the only dialog or chain an obligation can meet is the one it was raised in, and refusing it leaves no allowed way out. _(from Wonder, owner, 2026-10-04)_
- **`continue_battle` and `run` are never refused:** no rule binds them, and refusing them would leave a running battle with no allowed way on or out. _(from Wonder, 2026-10-04)_
- **Pokérus is ignored:** no guard, no obligation; the owner ruled it out of the EV rule: "if you're infected, ignore it". _(from Wonder, owner, 2026-10-04)_
- **The Day Care:** any deposit is refused at its deposit event; "ante la duda, no lo hagas". _(from Wonder, owner, 2026-10-04)_
- **The League:** walking or interacting through the gatekeeper's door is refused unless every living party member is at 75 and no blocking obligation stands; inside, on the Elite Four's map 172 and the Champion's map 173, `use_item`, `give_item`, `take_item` and the Pokévial are refused, and swapping the party order stays allowed. Both were Wonder's own rules ([Coverage](#coverage)). _(from Wonder, owner, 2026-10-04)_

### Party Rules

- **A legendary or mythical in the party never battles and leaves at the next PC.** The guard refuses `switch` into it, and it must never be the lead (the first able member). The audit raises "deposit at the next PC", which blocks the freeze and League entry until done. Why: refusing the catch alone would not cover gifts and hatches. _(from Wonder, owner, 2026-10-04)_
- **The seventh shiny:** the guard refuses a ball at a shiny wild Pokémon once 6 are counted. A seventh that arrives without a ball is a breach the engine cannot prevent; the audit raises "release at the next PC", and it never counts and is never used. Shinies are counted from any source, the dead and a shiny legendary included, by personal ID in the save ledger, so a release never lowers the count. _(from Wonder, owner, 2026-10-04)_
- **The living shiny in the party:** when the player owns a living shiny that is not a legendary, the party holds one. `store`, `pc` and `choose_pokemon` on the full-party store question's party screen are refused when their end state would leave none. If the party's shiny dies while another lives in the PC, the audit raises "withdraw at the next PC", which blocks the freeze. _(from Wonder, 2026-10-04)_

### Battle Clauses

- **Sleep Clause** is Showdown's Sleep Clause Mod, a guard on `fight`: a move whose own effect puts a foe to sleep is refused while any opposing Pokémon, on the field or benched, is asleep from one of our moves. Sleep from a secondary chance or an ability cannot be prevented and is allowed; Rest and other self-inflicted sleep never count. _(from Wonder, owner, 2026-10-04)_
- **OHKO and Evasion Moves clauses** are Showdown's lists: `fight` refuses the OHKO moves (by the game's OHKO function code) and Double Team and Minimize. Learning them stays allowed. _(from Wonder, owner, 2026-10-04)_

### Gym Freeze and Pastes

- **A badge count above the frozen pastes means a freeze is pending.** While it is, the guard refuses balls, gift interactions, egg withdrawals and levelling: Rare Candy and the EXP Candies are refused, and in a wild battle that can be fled `fight` and catching are refused, so the player runs. A battle that cannot be escaped is fought. Walking to a PC and rearranging the party stay allowed. Why: the rule's "before catching anything new", and no levelling between the gym and the export. _(from Wonder, owner, 2026-10-04)_
- **The freeze is the Showdown export, audited first:** only living Pokémon, no legendary or mythical, a shiny when one is owned, Species Clause. _(from Wonder, owner, 2026-10-04)_

### Build Choices

- **The copy:** `anil.harness.rules` is Wonder's `harness.rules` without `EGG_RULE`, the egg ledger (`Eggs`, the "Huevos" box count, `egg_refusal`), `RunFacts` and every `harness.runs` call; `anil_rules.rb` is Wonder's `wonder_rules.rb` under `AnilBridge`, installed with the bridge's game hooks and preloaded before `anil_bridge.rb`; `rules_bought` and `rules_shiny` are back among the kinds only the bridge writes. Withdrawing an egg while a freeze is pending is still refused, by the paste rule, since an egg opened is a new Pokémon. _(build choice, 2026-10-21)_
- **The frozen gyms live in the save's ledger:** `anil rules freeze` audits the party, prints the `anil showdown` export, and calls `AnilBridge.rules_freeze(gym)` through `eval`, which adds the gym to the ledger's `frozen` list; the gym due is one more than the gyms frozen, up to the 8th. Nothing is written to the data root. Why: Wonder counted the pastes as files in its run folder, and run records and paste files stay in Wonder; the save is the one place left that is tied to the game, and it rewinds with a restore as the rest of the ledger does. The `eval` is recorded, so replay runs it again at its tick. Verified in session `20261021-220452` (`anil`, booted into `catch-verde`): with a badge given by eval, `anil rules audit` showed "freeze the paste" for gym 1 and exited 1, `anil rules freeze` printed the party's paste and the ledger read `frozen` `[1]`, the audit then showed 1 frozen and none due, and a second freeze was refused as none pending. _(build choice, 2026-10-21)_
- **A forced fight is a `rules` record entry:** an allowed `fight` while a freeze is pending writes `stage` `forced` with the gym, the opponent (or `wild`) and each party member's species, level and exp, where Wonder appended it to its run's `log.jsonl`; refusals are in the `check` entries alone. _(build choice, 2026-10-21)_
- **The competitive-item list is the shop items with an in-battle held effect,** committed in `anil.harness.rules` as `COMPETITIVE_ITEMS`, drawn from every mart and Battle Point shop's stock: the ten held items of Ciudad Añil's mart, the 18 Gems, the nine incenses, the 19 pinch and battle berries and the 17 type-resist berries, and from the Torre Batalla's shop the held items of legendaries and mythicals, which cost nothing to count since a legendary is never used. Left off: balls, medicine, repels, drinks, evolution stones, Mega Stones, mints, vitamins, PP Up, the EV-reducing berries, the Mochis, the power items, and the form-change and key items. _(from Wonder, build choice, 2026-10-04)_
- **The ledger counts every purchase and every shiny,** not only the competitive ones, so changing the list never needs a new bridge. The buy count rises on each item the buy screen adds and falls on each it takes back; selling never lowers it. Verified in `anil` session `20261021-220452`: two Poké Balls bought at Ciudad Verde's clerk (map 31 event 8) wrote two `rules_bought` entries and the ledger read `POKEBALL` 2. _(from Wonder, build choice, 2026-10-04)_
- **Shinies are swept, not hooked one by one:** after every call that can give the player a Pokémon (`pbAddPokemon` and its kin, `pbStorePokemon`, `pbHatch`, the trades) and after every battle, the bridge appends any shiny in the party or boxes it has not counted yet. The harness also counts any owned shiny the ledger lacks, after the ledger's own. _(from Wonder, build choice, 2026-10-04)_
- **The first 6 shinies counted are the ones that count;** any later one is treated like a legendary for the party, plus a non-blocking "release at the next PC" wherever it is, since no verb releases yet. _(from Wonder, build choice, 2026-10-04)_
- **"Never the lead" is guarded and audited:** `swap` and `pc` are refused when their end state would put a legendary (or a shiny past the 6th) first among the living, and one already leading raises "move it off the lead", which blocks walking and `interact`. _(from Wonder, build choice, 2026-10-04)_
- **The living-shiny guard refuses only the act that takes the last one out:** when the party had none before, the "withdraw at the next PC" obligation stands instead, so depositing someone else is never blocked by it. _(from Wonder, build choice, 2026-10-04)_
- **The Day Care guard is its deposit event,** the Guardería's map 49 event 4 (`DayCare.deposit`); the Day Care Man on Ruta 5 (map 17 event 1) only collects eggs and is not refused. _(from Wonder, build choice, 2026-10-04)_
- **A `buy` is judged on its total per item,** so the same competitive item named twice in one call counts twice. _(from Wonder, build choice, 2026-10-04)_
- **League entry is the gatekeeper:** `interact` with map 132 event 16, continuing a dialog while that event runs, and a walk that ends on map 172 or 173. _(from Wonder, build choice, 2026-10-04)_
- **`Relearn` is always allowed:** no rule binds which moves a Pokémon knows, and the paste rule's "before catching or levelling" does not reach it, as it does not reach a TM. _(from Wonder, build choice, 2026-10-09)_
- **`anil rules check` takes the verb's own arguments:** `buy ITEM[=QUANTITY]...`, `use ITEM SLOT`, `give ITEM SLOT`, `take SLOT`, `swap A B`, `vial`, `pc OP...`, `interact MAP EVENT`, `walk [--map MAP]`, `dialog`, `menu`, `save`, `sell ITEM[=QUANTITY]...`, `exp-share SLOT on|off`, `fly TOWN`, `battle`, `run`, `switch SLOT`, `item ITEM` (a battle item), `fight MOVE` and `store pc|SLOT`. It prints `allowed`, or `refused by <rule>: <reason>` and exits 1. `anil rules audit` prints the obligations with what each blocks, the shinies counted, the competitive items bought and the freeze state, and exits 1 when one blocks. _(from Wonder, build choice, 2026-10-04)_
- **A foe is asleep from one of our moves when any move of ours put it to sleep,** its own effect or a secondary chance, the yawner's included; sleep from an ability, a partner's move or the foe's own move is not counted. The ledger records it per opposing Pokémon by personal ID. _(from Wonder, build choice, 2026-10-04)_
- **The sleep moves are the status moves with a sleep function code** (`SleepTarget`, `SleepTargetIfUserDarkrai`, `SleepTargetNextTurn`), read from the game database; the OHKO moves are those whose function code starts with `OHKO`; the evasion moves are Double Team and Minimize by ID. A refusal names the move, never the sleeping foe, which an Illusion may hide. _(from Wonder, build choice, 2026-10-04)_
- **The replacement and the next-Pokémon answer are `switch` itself,** so the `switch` guard covers them, judged on the battle's party. _(from Wonder, build choice, 2026-10-04)_
- **The `store` guard reads the catch from the battle's `store` payload,** which the bridge gives its shininess and personal ID ([Runtime → Payload Wrappers](../reference/runtime.md#payload-wrappers)). _(from Wonder, build choice, 2026-10-04)_
- **What a pending freeze refuses:** a ball in a wild battle; `interact` with, and continuing a dialog of, an event the game database mines as a `gift_pokemon` location; withdrawing any egg; Rare Candy and the five EXP Candies; and `fight` in a wild battle that the bridge's `run_refusal` lets the first able battler of ours run from. _(from Wonder, build choice, 2026-10-04)_
- **`anil rules freeze` is refused** when no freeze is pending, in a battle, with no living party member, while an obligation that blocks `freeze` stands, and when two living party members share a species ID (Species Clause; forms share the ID). _(from Wonder, build choice, 2026-10-04)_
